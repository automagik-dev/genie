## Summary

This wish plans how Genie:
1. Consumes the shared Rust usage meter (`~/.local/bin/usagemeter`, Contract 1 `contract_version: 1`, capability `meter.usage@1`, `usagemeter >= 3.126.1` per `meter/schema/query/v1/envelope.schema.json`, `docs/rfcs/0017-usagemeter-crate.md`, `docs/rfcs/0018-meter-query-contract.md`, `docs/rfcs/0021-meter-attribution.md`, and `docs/rfcs/0026-bot-tag-coverage.md`) across the Herdr Tasks board (`plugins/genie-herdr/data.js` `herdr-meter`, `docFeed`, `feedRows`, `refresh` and `crates/genie-rs`) and Genie's CLI reporting (`genie metrics export` in `src/term-commands/metrics.ts` `registerMetricsCommand`, `runExport` and `src/lib/metrics-export.ts`), retiring Genie's duplicate TypeScript session-log parser (`src/lib/metrics-usage.ts` `readUsageSamples`) and Phoenix OpenTelemetry span projection (`src/lib/metrics-phoenix.ts` `projectToPhoenix`) behind frozen shared-input comparison fixtures and a one-release deprecation path.
2. Closes the **learning loop** ("learn from our own past" and extract intelligence from people **naturally**) with a read-only, repo-agnostic Rust engine (`genie-rs learn` / `genie metrics learn`) built **only** over `usagemeter`'s JSON outputs (`usagemeter query` per `meter/schema/query/v1/envelope.schema.json`, `usagemeter outcomes --json` per `meter/usagemeter/src/outcomes.rs` `Record`, `WindowOut`, `ErrorsOut`, `TimeToPr`, and `usagemeter coverage --json` per `meter/usagemeter/src/coverage.rs` `Record`, `WindowOut`, `Totals`, `PartOut`) and standard public git/PR history — never locked to Genie-private data shapes — so Automagik can reuse the exact same intelligence capability for its own users from the ambient usage they already produce (adding **no** manual step, tag, or instrumentation a person has to do), while Genie serves as its **first consumer (dogfood)** without ever auto-editing files or bot definitions.
3. Operates **24/7 with zero daemon** by pairing blazing-fast fork-and-exit Rust commands (`<= 150 ms p95` for `genie-rs list --json`, `<= 500 ms p95` for `genie-rs learn --json`) with Herdr's 10-minute open-UI sync today (`herdr/mods/am-sidebar/meter.js` `"No LaunchAgent and no daemon"`, `METER_EVERY_MS = 10 * 60 * 1000`), documenting native meter backfill commands (`~/.local/bin/usagemeter sync --backfill` and `--evidence-backfill --days <N>`), and filing six explicit cross-repo **REQUESTS** (`REQUEST-1`..`REQUEST-6`) to the meter and Herdr pack owners for headless OS timers, generic post-sync hooks, fleet-wide roll-ups, and sub-task interval/outcome queries.

Full unattended 24/7 operation when the Herdr UI is closed and multi-machine fleet roll-ups are requested via six explicit cross-repo **REQUESTS** (`REQUEST-1`..`REQUEST-6`) to the meter and Herdr pack owners.
- **Part E — Everything Rust boundary:** Implementing the meter query client, canonical repo-slug normalizer, and portable learning-loop engine in `crates/genie-tasks` and `crates/genie-rs` now (with zero `genie-tasks -> genie-forge` dependency cycle; `crates/genie-forge/Cargo.toml` already declares `genie-tasks.workspace = true`), while keeping `src/term-commands/metrics.ts` and `src/term-commands/metrics-learn.ts` as thin TypeScript CLI front doors until Sibling Wish 1 (`genie-metrics-rust-cutover`).

- **Per-person rows, failure rates, labels, or rankings** (`usagemeter outcomes` in `meter/usagemeter/src/outcomes.rs` `NOTE` explicitly prints *"no rate, label or score"* and calls failures *"not a quality verdict on their own"*; Group 4 proposals are restricted to bot `(role, harness)` pairs and branch/task scope until `D1` and `REQUEST-2` are decided by the owner).

- Any modification to `usagemeter`, its SQLite store, its Contract 1 schema, or `herdr/mods/am-sidebar/meter.js` inside this repository (Genie is strictly a consumer; meter and Herdr pack capabilities are requested via `REQUEST-1`..`REQUEST-6` to the Automagik meter/herdr owners).

### Cross-Repo Requests to Meter & Herdr Owners (Not Genie Execution Groups)

- **`REQUEST-1` (to `usagemeter` owners — branch & task-keyed failure join in `usagemeter outcomes --json`, per-row priced `models[]`, and formal JSON schemas for `outcomes` and `coverage`):** Today `usagemeter outcomes --json` (specified by issues `#899`/`#1026` and `RFC 0018 (c)` in `meter/usagemeter/src/outcomes.rs` `RECORD_VERSION = 1`, `Record`, `WindowOut`, `ErrorsOut`, `ErrorLine`, `TimeToPr`, `BranchLine`) and `usagemeter coverage --json` (specified by `docs/rfcs/0026-bot-tag-coverage.md` and `meter/usagemeter/src/coverage.rs` `RECORD_VERSION = 1`, `Record`, `WindowOut`, `Totals`, `PartOut`) are local JSON records with top-level record version `v: 1` (explicitly marked *"not contract 1"* in `meter/usagemeter/src/main.rs`), `outcomes` groups failures (`tool_error`, `api_error`, `run_failed`) by `(bot, kind, role, squad, harness)` (`ErrorLine`) and time-to-PR by `branch` (`BranchLine`) and `(bot, role)` (`BotLine`), and `usagemeter query` rows emit `harness` and `cost.unpriced_models` (`$defs.cost` in `meter/schema/query/v1/envelope.schema.json`) rather than priced model names per row. Request that `usagemeter` (a) emit per-`branch` (and, when present, per-`task`) failure counts in `outcomes --json` so the learning loop can join failures directly to a branch/PR, (b) include an optional `models[]` breakdown on `usagemeter query` rows so `(role, harness)` efficiency comparisons can drill down to `(role, model)`, and (c) publish formal versioned JSON schemas under `meter/schema/` for `outcomes` and `coverage`.
- **`REQUEST-2` (to `usagemeter` owners — natural, zero-tag human PR & failure outcome attribution in `usagemeter outcomes` from ambient git/cwd evidence):** `usagemeter query --branch <b>` already attributes untagged human sessions by logged git branch (`tokens_by_branch_basis.log`), whereas `usagemeter outcomes` (`meter/usagemeter/src/outcomes.rs` `TimeToPr`, `ErrorsOut`) currently computes time-to-PR (`to_open_s`, `to_merge_s`, `launch_to_open_s`, `launch_to_merge_s`) from pull requests recorded in Herdr's `workers` ledger and attributes failures primarily through launch tags (`hc_snapshot`, `workers_ledger`). Because Automagik will extract intelligence from people **naturally** (once `D1` is approved, with zero manual tags or `herdr worker` wrapper required), request that `usagemeter outcomes` also attribute branch-level failure counts and PR timing from the ambient `cwd` + git branch evidence (`evidence.rs` / `scan.rs`) that `usagemeter sync` already collects from local harness logs (`no_record` / human interactive sessions).
- **`REQUEST-3` (to Herdr pack / `automagik-herdr` owners — opt-in headless 24/7 OS timer for `usagemeter sync`, amending `meter.js`'s no-LaunchAgent rule):** Today `herdr/mods/am-sidebar/meter.js` explicitly states `"No LaunchAgent and no daemon"` as the pack's design, running `usagemeter sync` every 10 minutes (`METER_EVERY_MS = 10 * 60 * 1000`) only while the Herdr desktop window is open. Request that the Herdr/meter owners amend that rule so `automagik-herdr meter install` offers an opt-in, daemon-free OS timer (`systemd --user` timer on Linux, `launchd` `StartInterval` on macOS) that runs `~/.local/bin/usagemeter sync` every 10 minutes when the Herdr UI is closed (e.g. on a headless build box or when the owner's laptop lid reopens), sharing the meter's 10-minute freshness gate.
- **`REQUEST-4` (to Herdr pack & `usagemeter` owners — multi-machine fleet roll-up for `query` and `outcomes`):** Today `am-sidebar/meter.js` and `am/meterFleet.js` combine `usagemeter coverage` across connected linked machines (`hc exec --on <machine>`) into `fleet-coverage.json` and publish per-machine `herdr-meter` summary docs, but neither `query` (`--by task` / `--branch`) nor `outcomes` is rolled up across machines. Request a read-only fleet roll-up (`fleet-usage.json` / `fleet-outcomes.json` beside `fleet-coverage.json`, or `automagik-herdr meter fleet-query`) combining aggregate envelopes across machines without moving raw transcripts.
- **`REQUEST-5` (to Herdr pack owners — generic opt-in post-sync hook in the `REQUEST-3` headless timer):** Request that the `REQUEST-3` headless timer support a generic, opt-in post-sync hook list in user config (invoked fork-and-exit at most once per 24 hours after a clean `usagemeter sync`) that any consumer can register into, so the Herdr meter pack never names Genie or any Genie-specific binary. (While the Herdr desktop UI is open, Genie's own `plugins/genie-herdr` triggers per-project `genie-rs learn --project <p> --window d7 --json --write-latest` at most once per 24 hours.)
- **`REQUEST-6` (to `usagemeter` owners — optional `[--since <rfc3339> --until <rfc3339>]` or session/transition interval filter and longer windows on `usagemeter query`):** Today `usagemeter query` supports `--window d1|d7|d30` only (`window.name` enum in `meter/schema/query/v1/envelope.schema.json`, `attribution.precision: "task_interval"` or `"branch_window"` per `docs/rfcs/0021-meter-attribution.md`), whereas `genie metrics export` (`src/lib/metrics-export.ts` `readCaptureLedger`, `buildIntervals`, `sumUsage`) historically sliced a single session's JSONL log into sub-task transition intervals (`claim -> report`) from `<GENIE_HOME>/metrics/events.jsonl` (`src/lib/metrics-capture.ts` `captureLedgerPath`). Request optional RFC3339 interval bounds (`--since` / `--until` or `--session <id>`) on `usagemeter query` to restore sub-task transition token slicing (`D5`), plus an optional `--window d90|all` selector for tasks and learning windows older than 30 days.
