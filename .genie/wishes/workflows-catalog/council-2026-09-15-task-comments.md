Risks or objections:
- Attribution collapse: with no `--worker`/`--author` on `comment`/`report`, every engineer whose runtime lacks GENIE_AGENT_NAME posts as `cli` (7/9 rows today), so the 'conversation' shows one anonymous speaker — the feature's whole value is who said what at which handoff.
- Cap arithmetic per group: one group lifecycle is already ~claim + release + move (3 events) per handoff; with a comment at every handoff plus a review relay plus B=2 fix loops you reach ~12-16 events, leaving little headroom before the oldest (the kickoff context) drops off the tail. Any heartbeat-style comment cadence blows the 25 cap within a single long group.
- Board-wide degradation: the byte step-down (25→10→5→2→0) is computed over the whole board aggregate, so verbose comments on many cards degrade every card's history simultaneously and silently (DSH only shows `last N of M`).
- Git coupling contradicts the 'operational state, not a second ledger' framing: every comment lands in the git-tracked roadmap.json via the pre-commit export, inflates feature-branch diffs, and produces textual merge conflicts on roadmap.json between concurrently shipping branches; sync-level divergence between two clones/machines is resolved winner-takes-all, discarding one side's comments.
- Contract drift between CLI and plugin: the plugin's strict Zod schema requires eventLimit/eventCount/eventsTruncated/commentCount that this branch's src does not emit — the source of truth for the cap is a released binary this checkout lags (local origin refs stop at v5.260909.1, remote tags reach v5.260915.7). Decisions made on 'eventLimit=25' are pinned to unreleased-in-this-tree code.
- Orca mode: a skill that says 'MUST post a comment' will fail hard on `assertLocalLifecycleEnabled` unless the prose carries the same 'no task row / db unavailable → skip' clause as checkout/done.
- Letting the reviewer write comments breaks two stated invariants in review/SKILL.md and makes the pinned detached-worktree review (which resolves the shared genie.db via git-common-dir) a writer — the read-only snapshot guarantee would be prose-only.
Required conditions:
- Reviewer stays read-only: the orchestrator relays the verdict as `genie task comment <id> 'REVIEW: SHIP|FIX-FIRST|BLOCKED — <one-line gap summary>'` at the same moment it appends the evidence block to WISH.md; the card comment is a pointer, WISH.md keeps the evidence.
- Fix the attribution gap before mandating cadence: either add `--worker <name>` to `comment`/`report` (mirroring `checkout`) or require the engineer brief to export GENIE_AGENT_NAME=<engineer-name>; add a test asserting a report authored under a named worker records that name, not `cli`.
- Assign distinct moments, do not collapse: `report` = engineer-authored, exactly one per checkout-to-handoff span (completion summary or blocked reason); `comment` = orchestrator/human/relayed-reviewer at dispatch, review verdict, and done. This matches the existing schema asymmetry (`comments`/`commentCount` exclude `report`; DSH UI exposes only `comment`).
- Cadence ceiling written into both skills: at most one `report` per engineer handoff and one `comment` per orchestrator gate (dispatch, review, done); no periodic progress comments — liveness uses `genie task heartbeat`, which is already event-free. Budget target: ≤ ~12 events per group lifecycle so a full fix loop stays under the 25 tail.
- Skill prose carries the same degrade clause as checkout/done ('no task row / db unavailable / orca mode → skip the comment, never block'), and the mirrored copies stay byte-identical (note: plugins/genie currently ships no skills/ tree — confirm where the mirror actually lives before claiming parity).
- Bound comment length at the CLI to the DSH bound (4000 chars) or lower, and reference commit SHAs/paths instead of pasting logs, so the board-wide 3.5 MiB step-down stays far away.
- Decide explicitly whether task_events should keep riding roadmap.json; if yes, document that comments are git-persisted and that cross-clone divergence loses one side, and add a merge-conflict note to the work skill's commit step.
Unknowns:
- Where the eventLimit producer lives in source: it is present in the installed 5.260915.6 binary but absent from this checkout and its stale origin/main and origin/dev refs; the cap semantics (tail-keep, board-wide byte step-down) were read from `strings` on the binary, not from reviewed source.
- Whether 'mirrored into plugins/genie' is still true — plugins/genie holds no skills directory in this checkout (only orca-entrypoint, plugin manifests, references), so the portability constraint may refer to a mirror that no longer exists or lives elsewhere.
- How engineer runtimes actually set GENIE_AGENT_NAME/GENIE_AGENT_KIND across Claude Code, Codex and DSH dispatch — the db shows Codex and Hermes comments all attributed to `cli`, but the dispatch env was not inspected.
- Whether the roadmap.json three-way sync is exercised across multiple clones in practice (single-machine worktrees share one genie.db and skip the hooks), which determines how real the comment-loss-on-divergence risk is.
