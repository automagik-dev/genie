# Council Report: Brainstorm and validate a design for landing the verified three-harness audit findings in the genie repo (/Users/feliperosa/workspace/repos/genie): three fixes already sitting uncommitted in the working tree (schemaIsCurrent backfill skip, freshness handler prompt-injection channel, shortcuts uninstall heuristic), plus two open findings needing a decision (unfenced completeTask allows completing another worker's claimed task; dead wish-group machinery documented in TAXONOMY but with zero production callers). Run autonomously — no user back-and-forth; produce a SHIP-stamped design the wish skill can consume.

## Executive Summary
The council converged on a SHIP-stamped design: one wish, three independent groups, and a shared precondition gate. Gate zero is bun >=1.3.10 plus a clean-HEAD stash-and-retest attribution run; Group A commits the three ready working-tree fixes as three separate commits; Group B ships the completeTask CAS fence (on `claimed_by`, mirroring releaseTask, no force knob) after enumerating callers and defining undefined-author semantics; Group C deletes the dead wish-group TypeScript machinery, TAXONOMY prose, and mcp-tools read paths while keeping the table DDL inert as vestigial. The 13 failing codex-delivery tests are unattributed observations, not findings — they stay out of the wish unless they survive the gate under 1.3.10.

## Consensus
- Wish shape: three independent groups (A: ready fixes, B: completeTask fence, C: wish-group deletion) so a stall in any decision never holds the finished fixes hostage — Group A is commit-gate-PR, not a redesign.
- Gate zero (unanimous by Round 2, stated as a precondition, not a group): upgrade bun to >=1.3.10 (package.json engines pins it; local is 1.3.9), then stash-and-retest — run the suite on clean HEAD, then on the working tree — and only failures surviving both become deliverables. shortcuts.test.ts is untracked and the tree was never baselined as a unit, so 'verified' needs this receipt.
- The 13 failing codex-delivery tests are unattributed observations produced under an explicitly unsupported runtime on a dirty tree; do not design fixes for them in this wish. Survivors after the gate become a separate finding/trace task with its own root-cause investigation.
- The three uncommitted fixes (schemaIsCurrent backfill skip, freshness handler prompt-injection rework, shortcuts uninstall rewrite plus new test) are architecturally sound contract repairs, ship as-is as three commits with their tests, with no hardening riders, config flags, or follow-up scope attached.
- The completeTask fence ships in this wish. completeTask (task-state.ts:764) violates the never-clobbered invariant its siblings document: getTask read then an unconditional UPDATE with no status predicate or claim fence. Fix mirrors the existing claimTask/releaseTask CAS-in-SQL idiom, translating zero-changed-rows into a typed error shaped like releaseFailure.
- The fence column is claimed_by, not assignee — assignee exists only on wish_groups; the tasks table's claim column is claimed_by (verified independently by questioner and perf against genie-db.ts:513 and task-state.ts:366/:718/:813). The SHIP artifact must pin the exact SQL verbatim.
- No force/override knob on the fence. No current caller needs one; force-release-then-complete already composes from existing verbs; an admin-override story, if it ever appears, arrives with its own wish.
- Acceptance test for the fence: two authors race, the non-claimant's complete is refused with a typed error — plus questioner's third case, an authorless complete against a claimed task.
- Wish-group deletion is asymmetric (architecture's split, adopted by all four): delete the dead state machine, typed errors, mcp-tools read branches (:249, :337), export field, and the TAXONOMY state-machine section; keep the inert CREATE TABLE IF NOT EXISTS wish_groups DDL noted as vestigial-pending-drop, with no schema version bump. Dropping the table from live user DBs is a real migration under the same lockstep contract the schemaIsCurrent fix protects, and knownWishSlugs' UNION (task-state.ts:1167) and the export table list depend on the schema surviving.
- group_name on tasks is live (task-state.ts:369, 388, 487, 1498, launch.ts) and is explicitly carved out of the deletion — the dead thing is the execution state machine, not task grouping.
- importState must tolerate-and-drop the legacy wish_groups snapshot array (it currently INSERTs at task-state.ts:1536) rather than error — legacy-snapshot import is the exact class of hole the schemaIsCurrent fix in this same wish closes.
- Group B gains a required sub-task before the SQL is written: enumerate completeTask's callers, state which pass author today (author is optional at every current call site), and define undefined-author semantics explicitly — the fence is mechanical in SQL but not in call-site semantics.
- The mcp-tools deletion must either preserve the MCP response's groups field as a literal empty array or first verify no MCP consumer (ui-bridge, genie UI) reads it — removing a response field is a contract change and must be named in the wish, not smuggled into cleanup.
- The bun drift itself is not a code change or a finding — it is purely the precondition gate.

## Tensions
- Hyperfine baseline as merge gate (unresolved): perf insists the freshness handler — a PreToolUse hook taxing every guarded tool call — must carry a measured hyperfine baseline against the hook timeout ceiling before merge ('a 30-second gate protecting the hottest path in the product — that is not ceremony'). Simplifier calls this exactly the inflation the design must refuse: the diff's marginal cost is noise by perf's own analysis, and a handler-latency baseline is a separate observability task, not a gate on a ready security fix. Three of four members did not endorse the gate; the wish author must decide whether the number is captured in the commit lane or spun out.
- Wish-group archaeology (unresolved): architecture requires the deletion to cite the original wish/brainstorm that introduced wish_groups and confirm no SHIP-ready plan depends on wiring it into work orchestration — if one exists, the decision flips from delete to wire-or-defer. Simplifier and questioner counter that a minutes-long grep of .genie/ for an in-flight dependent suffices, and 'archaeology into why dead code was born is not a precondition for removing it; git history keeps the answer either way.' All agree on the in-flight-dependency check; the depth of provenance research is the open question.
- Whether the fence is 'mechanical': architecture and perf characterized the CAS fence as mechanical; questioner located a specific crack — author is optional and the code does author?.author ?? undefined, so a naive claimed_by IS NULL OR claimed_by = ? bound with NULL refuses every authorless caller from completing any claimed task, including a worker completing its own claim without threading identity — 'a regression dressed as a fix.' Questioner's proposed semantics (undefined author may complete unclaimed tasks only; completing a claimed task requires a matching author, with every claim-then-complete caller shown to thread identity before merge) was not contested but also not explicitly ratified by the others.
- Justification framing for the fence (resolved in outcome, not in principle): questioner framed ship-vs-defer as hinging on whether a production path exists where worker X completes worker Y's claimed task; architecture pushed back that the file's own doc comment declares the never-clobbered invariant, so the fence repairs a stated contract regardless of observed exploitation. Both land on ship; the disagreement is about what evidence future fences of this kind require.

## Evolution
Round 2 was dominated by verification against the tree correcting Round 1 claims. The largest reversal was on wish-group deletion scope: simplifier and questioner both started at "delete it all, drop the table, no deprecation period," then converged on architecture's schema/code asymmetry after simplifier verified the table sits inside the versioned schema (CURRENT_SCHEMA_VERSION, expected-columns map, DDL) and that dropping it entangles with the very schemaIsCurrent lockstep fix this wish ships — "deleting code while leaving the table inert is the genuinely simpler move, and I missed it." In the other direction, simplifier's discovery that getWishGroups is called from mcp-tools.ts (:38, :249, :337) falsified architecture's Round 1 claim that the machinery was referenced only from task-state, genie-db, and tests; architecture retracted it explicitly, widened Group C to include the mcp-tools read paths, and added the MCP groups-field contract obligation. Perf's cost model was corrected the same way (not just cold-start parse weight but per-call guaranteed-empty queries on the MCP path). Two precision fixes hardened the fence spec: questioner and perf independently caught simplifier's wrong column (assignee → claimed_by), and questioner escalated the optional-author parameter from a warning into a required caller-enumeration sub-task, softening the "mechanical fix" framing. The bun gate and clean-HEAD attribution step moved from individual suggestions to unanimous precondition status, with perf noting its own gate-zero argument depends on exactly that hygiene. The group_name carve-out and importState tolerate-and-drop, absent from every Round 1 position except architecture's and simplifier's respectively, ended Round 2 as shared obligations.

## Dissent
Perf, on the hyperfine baseline as a merge requirement (held through both rounds against simplifier's objection): "the wish must carry a measured baseline for the handler (`hyperfine` on the shipped bundle with a fixture payload) against the hook timeout ceiling, because that number is currently unknown and this handler taxes every tool call in every session." And in Round 2: "the freshness handler is a PreToolUse hook taxing every guarded tool call in every session with no measured baseline against the hook timeout ceiling. A hyperfine number on the shipped bundle is a 30-second gate protecting the hottest path in the product — that is not ceremony, and it stays in the commit lane."

Architecture, on wish-group provenance research before deletion (rejected by simplifier and questioner as archaeology, not retracted by architecture): "Before the delete lands, the wish must cite the original wish/brainstorm that introduced wish_groups and confirm no SHIP-ready plan depends on wiring it into `work` orchestration; if one exists, the decision flips from delete to wire-or-defer and that is a scope question for the council, not a code edit."

Questioner, on the evidentiary standard for the fence (architecture pushed back that the stated contract suffices regardless): "the question that decides ship-vs-defer is: does any production path exist where worker X completes worker Y's claimed task? Genie's dream skill batch-orchestrates concurrent workers, so the hazard is real, not theoretical — multi-runtime is this system's whole premise."
