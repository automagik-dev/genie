## PRODUCT lens — genie v6 "corpo leve" rev. 3

### 1. Lens response block

**Verdict:** SHIP-WITH-CONDITIONS. Deleting `plugins/` + the Codex/Hermes/pi delivery machinery is the right product call; the "two skillsets by install mode" framing is where the user-facing risk sits.

**Confidence:** High on deletion (evidence overwhelming); Medium on skills.sh as the sole delivery vehicle (it ships SKILL.md only — verified); Medium-low on "orca mode = separate skillset".

**Key evidence**
- `README.md` "Install"/"Codex surface boundaries"/"fallback quarantine" sections: ~5 screens of prose a new user must digest about delivery vs activation, five inventories, `.genie-codex-fallback-retirement/txn-<id>/…`. That is the product cost of `plugins/` + `src/lib/codex-*`, `install-promotion`, `agent-sync` (~25k LOC listed in brief) — none of it is what "Wishes in, PRs out" promises.
- `plugins/genie/hooks/hooks.json`: only three hook behaviours exist — SessionStart context (`session-context.cjs`), PreToolUse dispatch (branch-guard/freshness/identity/omni/git-freeze/audit), and `validate-wish.cjs` on Write/Edit. The base skills already cope without them: `skills/work/SKILL.md:108` "No task row? … task tracking is an enhancement, never a blocker"; `skills/wish/SKILL.md` step 10 runs the linter explicitly; `skills/genie/SKILL.md` "Bare skill invocation" does `ls .genie/wishes/*/WISH.md` itself.
- skills.sh / `vercel-labs/skills` (fetched): discovers `SKILL.md` under `skills/` up to 3 levels deep, installs by **symlink or copy** into `./<agent>/skills/` or `~/<agent>/skills/`, 77+ agents (Claude Code, Codex, Cursor, OpenCode, Cline, Copilot…), `update`/`remove`/`list`. **"No native support for MCP servers, scripts, or agent configuration files — only SKILL.md content"**; hooks only for Claude Code/Cline/Kiro. → hooks, `agents/*.md` role profiles, `workflows/council.js`, `rules/`, `references/` lose their delivery vehicle.
- Skills coupled to the board (grep `genie task|genie board|genie.db|roadmap.json`): `brainstorm` (`:117 genie task create`), `wish` (step 9, step 12 `genie context`), `work` (checkout/done/list throughout), `review` (`:192 genie task done`), `genie` router (whole "Operational Command Mapping" table), `fix`, `dream`, `pm`, `report`, `repo-hygiene`. Ten of 22 skills mention it; only `work`/`wish`/`review`/`genie` are structurally dependent.
- `docs/`: `docs/cli/{agents,dispatch,messaging,spawn,directory,registry,scheduling,database,infrastructure,session,team,projects,observability,releases-tags-types}.mdx`, `docs/architecture/{postgres,messaging,scheduler}.mdx`, `docs/concepts/{teams,agents,projects}.mdx`, `docs/skills/{wizard,learn,brain,loop-overview}.mdx`, `docs/config/{hooks,tmux,worktrees}.mdx` describe **v4** (pgserve on port 19642, `genie agent spawn/kill`, `/wizard`) — none of those commands exist in `src/genie.ts`. `.docs-vendor/docs.json` still navs all of them publicly. The public docs are already wrong today; rev. 3 is the moment to cut them.
- `DESIGN.md` rev. 2 keeps standalone semantics OUT and invents `execution.mode` in `~/.genie/config.json` + `.genie/config.json` + `GENIE_MODE` + `mode=` hook token + `--mode` validator fixture + mutually exclusive skill descriptions + guards in every base skill. That is five mechanisms so one prose file can pick one of two prose files.

**Risks / objections**
- Two same-named lifecycles (`wish` vs `genie-orca-wish`) in one skills.sh package = auto-selection ambiguity in every runtime (the DESIGN itself admits this, Risk 5, and pays for it with guards in three base skills). With skills.sh there is no hook to inject `mode=`, so the guard has nothing to read unless the skill shells out to `genie context`.
- Deleting `plugins/genie/hooks` removes `branch-guard`, `git-freeze-guard`, `audit-context` — the only *enforced* safety (skills are prose). For a solo maintainer that's acceptable; for a public product it's a silent downgrade. Say so in the README.
- `omni` skill + `genie omni serve` + `src/hooks/handlers/omni-approval` depend on the PermissionRequest hook (H6). Without plugin hooks the approval queue has no producer → omni becomes dead weight unless re-homed.
- `genie mcp` write tools (`genie_task_checkout/done/…`, `src/lib/v5/mcp-tools.ts:954–1118`) are the only non-hook way an agent gets state; standalone mode must keep `genie init` writing `.mcp.json` (`src/term-commands/init.ts:137`) or the board is invisible to Codex/Cursor users.

**Required conditions**
1. Orca mode is **a flag on the same skills**, not a second skillset: `wish`/`work`/`review` gain an "## Orca dispatch" section gated by a repo-level `.genie/config.json` (`mode: orca`) read by the skill via one shell call (`genie context` already planned to print `mode=`). Keep `genie-orca-work` as the only separate skill if the loop truly cannot be one file — it is the only one with a genuinely different control flow (Run/Task/worker_done vs claim/done).
2. Publish `skills/` to skills.sh with **one** router (`genie`) whose State-Detection table branches on mode; remove the "Operational Command Mapping" cockpit rows that name deleted verbs (`ui-bridge`, cockpit, "launch").
3. Lint gate: `scripts/skills-lint.ts` fails on any `genie task`/`genie board` mention inside an orca-gated section, and on `haiku|sonnet` in dispatch examples (`skills/genie-orca/work/SKILL.md` "Model routing" still says `claude --model sonnet` — contradicts its own "Model rule").
4. Docs: delete every v4 page listed above from `docs/` **and** `.docs-vendor/docs.json`; rewrite `installation.mdx`/`quickstart.mdx` to two paths (`npx skills add automagik-dev/genie` + optional `genie` CLI for the board).
5. `genie doctor` becomes the deprecation surface: detects a leftover `~/.genie/plugins`, `~/.codex/agents/genie_*`, `.codex/config.toml` marker, `~/.agents/skills/.genie-codex-fallback-retirement` and prints the one-line removal — do not carry `uninstall`'s classifier code forever.

**Unknowns**
- Whether SessionStart injection matters to users at all: `session-context.ts` emits ≤2 KiB slugs/statuses. Base skills re-derive the same in two `ls`. My read: it dies without loss; verify with one week of dogfood.
- Codex/Hermes external users: `README` "Personal skills… This maintainer currently has 36" — evidence that the only measured Codex user is Felipe. Deprecate in CHANGELOG, not with a compatibility layer.
- Whether skills.sh's Codex target honours `$genie:` owner-qualified selectors — every SKILL.md carries the "Runtime syntax… owner-qualified selector" paragraph (`skills/wish/SKILL.md:8`, etc.), which becomes false prose once the plugin is gone. Strip it from all 22 files.
