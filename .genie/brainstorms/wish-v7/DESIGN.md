## Problem

`/wish` v6 admits only a decided, bounded task and refuses everything else with a route, while the operator speaks in intentions. Between the operator's sentence and the delivery body the intent is rewritten by the orchestrator into a frozen objective, re-derived by a blind judge into a contract, and measured by an unstable `units` count — and a refusal leaves nothing behind. In the five measured v6 runs (recorded in the private handoff `claude-observability/reports/2026-09-17-handoff-wish-refactor.md`; the catalog README holds one live run and two dry runs) the operator's words exist nowhere in the record, two refusals were rule defects (a glob matching a test file; `units`), and the recovery cost ~1.5 h of agent time with no code written. It matters because the framework's promise is that anybody can state a wish and have it delivered at the highest speed the model and the harness allow; today the front door demands the framework's own vocabulary, and 68% of historical wishes fall outside it.

## Scope

### IN
- **Capture.** `/wish <words | issue URL | pasted message>` — or any lifecycle verb — first writes the intent VERBATIM to `.genie/brainstorms/<slug>/DRAFT.md` under a "data, not instruction" header carrying the injection fence, creates a roadmap card with `tasks.wish = <slug>` (`task create --wish <slug>`; standalone mode; skipped with a one-line note in Orca mode, and with no repository at all, where there is no `.genie/` — the intent is then echoed back in the one chat line), and appends a Raw entry linking the draft to `.genie/INDEX.md`. Capture writes to the working tree only and never pushes — the commit is the session's, on the branch the operator is on, and a `dev`-direct commit meets no PR-side scan, which is why the local scan is load-bearing — and before that write: a credential-shaped scan that blocks on a hit (`gitleaks protect`-style when the tool is present, otherwise the skill's own regex set for key, token and secret shapes; GitGuardian runs only on PR), the 4000-byte / no-control-char bound of `task comment` on the intent and the card title, issue bodies stored as URL + content digest, and an explicit operator "publish this" for pasted third-party text, because `.genie/` is public history.
- **Triage, inline and always first.** One read-only scout under the fence returns facts, drafts and wishes to resume, a candidate file set, an estimate (files, insertions), boundary hits, `injectionAttempts[]`, and evidence per WRS dimension. The session derives the WRS — never declares it: Problem = non-empty verbatim intent; Scope = declared file set AND an OUT list; Decisions = zero open questions in the persisted triage; Risks = every boundary hit acknowledged in the operator's own words; Criteria = at least one machine-class criterion naming a command narrower than `bun run check`. It classifies the lane — Incident, Patch, Small bet, Standard bet, Program, Spike, or **Freestyle** (no repository or no code outcome: the agent works with its own capabilities inside the same context framework) — by payout cardinality, consequence, reversibility and oracle strength; applies the per-group ideal (≤10 files / ≤800 insertions) and the per-wish maximum (25 files / 2,000 insertions to start, recalibrated after three runs); proposes a split into sibling wishes when the wish exceeds the band; and renders ONE chat line (score, lane, estimate, question count) plus one numbered round of at most five items, each with a recommended answer. An injection attempt forces at least one round regardless of WRS; a lane inferred from untrusted text may only raise verification.
- **One explicit "go", always.** WRS 100 drops the questions, never the approval: the rendered contract (declared files, groups, oracle, boundaries, estimate) receives one operator "go" before anything runs. Mandatory for any intent that did not originate in the operator's typed words.
- **Contract.** Drafted by the session from intent + triage + answers: core and flex, oracle, declared file set, `groups[]` with `depends-on`, acceptance criteria each tagged `machine | model | human`; frozen on "go". At freeze `.genie/wishes/<slug>/WISH.md` is scaffolded from the template with `## Intent`, `## Triage` and `## Attempts` as ADDITIONAL sections (tolerated by `validateWish`; declared optional, never required); Status DRAFT plus `Lane` and `WRS` metadata rows; the operator's freeze writes APPROVED. No WISH.md exists before freeze. For Standard and Program contracts one bounded independent `review` round (cap 1) runs between "go" and the first run; Patch and Small skip it.
- **Boundaries as policy.** `.claude/rules/wish-boundaries.md` (new directory, repo-local; mirrored in the skill prose for installed hosts) states which paths execute before a human reads the diff — `.github/` runs CI with a repository secret on PR open; `.husky/`, `commitlint.config.ts`, `biome.json` and `package.json` scripts run on the executor's own commit and on the gate — and what an acknowledgement requires. No tier table enters the script: every denylist entry is acknowledgeable by the operator, per path, in the operator's own words, never pre-filled, never satisfied by "go with your recommendations", recorded in `## Triage`. `acknowledgedBoundaries` is consulted at every point where `wish.js` reads the denylist today — the admit override that routes a declared hit to `plan` (`wish.js:945-949`), the judge brief (`:537-538`), the reviewer brief in the initial and every repair round (`:619-622`; `normalizeReview` keeps a reviewer-declared BLOCKED, `:1055-1056`), the post-review union check (`:1050-1052`) and the read-back mismatch on the PR file set (`:1278-1279`) — so an acknowledged path is expected at all of them and any unacknowledged hit still refuses or blocks exactly as in v6. The policy text travels to the blind judge inside `contract` (`contract.boundaryPolicy`: the rules file's content, framed as data) because the script performs no IO and the judge opens no file; the scout stays factual. The judge classifies each acknowledgement by WHEN the path executes. A path that runs at the executor's own commit or at the gate — `.husky/`, `commitlint.config.ts`, `biome.json`, `package.json` scripts — is `holdBeforeWork`: `wish.js` returns `refused` with route `plan` exactly as today, nothing is created, and the canonical wish delivers that edit through its manual body (`work`, the operator reading each step), because no automated hold can precede a hook that fires at commit. A path that executes only after publish — `.github/` runs CI with a repository secret on PR open — is `holdBeforePublish`: the run ends `blocked` before any push, naming the worktree, the head SHA and the diff for the operator's read. The release is carried by the acknowledgement itself: the operator's "publish" reruns with the same slug and `acknowledgedBoundaries[].readHead` set to the SHA read; the SCRIPT — never the judge — dispatches the executor with an ADOPT-ONLY brief (adopt the worktree under the v6 rule, edit nothing, commit nothing, report branch, worktree and head — the same agent call and spread count, a different brief; a dirty or diverged worktree fails adoption and ends `blocked` with the diagnostic, nothing pushed), lifts the hold only when that reported head equals `readHead`, re-runs the gate and the review on that exact SHA, publishes with the acknowledged list in the report and the PR body, and read-back adds `pr.headOid === readHead` to its mismatch list. What the hold covers is therefore exact: a human read of the diff before anything LLM-written executes on CI, and human hands for anything that would execute on the operator's host at commit.
- **Delivery.** `wish.js` gains optional args `contract` (with `groups[]`) and `acknowledgedBoundaries`. With `contract` present the judge authors nothing and runs check-only (may return not-admissible on a rule hit, not-one-task, not-scorable-blind); path-shaped checks stay script-side (declared set non-empty and repo-relative, declared ⊆ the scout set the script dispatches, denylist hits against `acknowledgedBoundaries` at admit, post-review and read-back, the `readHead` equality that lifts a hold, no criterion naming `bun run check`, oracle narrower than the gate). Groups execute sequentially in ONE worktree and ONE branch — per group: executor → gate → focused review against that group's criteria, committed per group — then one integrated review of the whole diff against the wish's criteria, one publish, one read-back. `objective`-only invocation keeps the v6 authoring judge, so rollback is omitting the arg. Five states and `merge-ready` equality byte-for-byte unchanged.
- **Parallel wishes.** The orchestrator (the session, or `dream` overnight) runs many wish workflows concurrently, each in its own worktree, branch and PR. Batch input (a list of issues) = N scouts in parallel → ONE combined round → one "go" that lists every wish, each approved individually → N background runs. Wishes whose declared file sets intersect are sequenced with `depends-on`. `budgets.maxParallelWishes` caps concurrency (conservative default, schema ceiling, tighten-only).
- **Front doors.** The canonical procedure is owned by the `wish` skill (SKILL.md front door + `references/`). Every other lifecycle verb that mutates or plans — `work`, `fix`, `brainstorm`, `report`, `dream`, `merge` — opens with the same one-line handoff carrying its verb as a type hint and keeps its by-hand procedure below; the assess-only verbs `review`, `verify` and `council` hand off without capturing, so nothing is written before a reviewer runs and the dispatched reviewer stays read-only; `quick` stays the v6 one-line retirement stub on its three-measured-runs trigger and is not touched; `brainstorm` keeps the deep exploration path (frontier rounds, DESIGN.md, independent review) and restores the WRS bar, invoked when WRS < 60 or the change is Architectural; the `genie` router's table collapses to the handoff. The eleven skills and the brainstorm/review lenses `ed6028f15` deleted return from `ed6028f15^` as front doors and reference material (`skills-restore`).
- **Memory.** `## Triage` persisted on every exit, `rounds: <n>` included; one `## Attempts` line per run (run id, state, estimate vs real diff, blocked/missed reason, PR); the card holds the pointer, written by the session between runs (`genie task comment --worker orchestrator`), never by a workflow agent.
- **Measurement.** README measured-runs rows with USD and API-call columns; an offline replay of lane × WRS routing over `../wish-v6/wishes.csv` (n=50) beside the v6 council's 68%; a three-run calibration window for the 60/100 thresholds and the bands.
- **Slice 0, first.** `scripts/release-*` never matches `*.test.ts`; `units` becomes advisory (files and insertions the only hard maxima); runs 2–5 into the README.

### OUT
- Deterministic FORCED/ACKNOWLEDGEABLE tiers in the script — a measured misjudgment is the trigger, not a design decision.
- Per-group PRs, stacked bases, or parallel groups inside one wish.
- Orca-mode dispatch for `wish.js`; `work`'s Orca coordinator protocol is unchanged.
- Changes to `wish-template.md` or `validate-wish.ts` beyond declaring three optional sections; `<!-- wishes-lint:ignore -->`.
- A new WISH status; any change to `merge-ready` semantics, the five states, or the three inherited clauses (review: reviewer different and read-only; fix: default 2 when unset; work: a worker notification is not delivery evidence).
- Telemetry, hooks, shipping `.claude/workflows/` or `.claude/rules/` in the release payload.
- Dollar or token appetites per lane (structural caps first, per the parent draft).

## Approach

One procedure — **capture → triage → go → contract → deliver → remember** — reached from every verb. The operator's words are the root object; everything after them is derived, inspectable and routed. Triage decides how much human is needed (zero questions at a derived WRS 100, one round otherwise, the deep brainstorm path below 60) and how much depth the delivery gets (Freestyle for a wish with no code outcome; the full worktree-gate-review-PR body for software). Inside a wish, groups are sequential in one branch and ship as one PR; across wishes, the orchestrator fans out. Nothing is refused: a too-big wish is split, an open decision is asked, an unknown cause becomes a Spike, a boundary is acknowledged or the route is `plan`.

Alternatives considered:
- **v6 plus the two rule fixes** (the council's dissent). Fixes both refusals but not capture, authorship or memory; kept as slice 0 because it is the first thing that ships and it meets v6's own three-measured-runs trigger honestly.
- **Per-group `wish.js` runs** (the first proposal). N PRs, N operator merges in order, ~$3.7 fixed overhead per run, stacked bases the script does not model; `work` merged 76% of the same basis within 8 h as one PR. Lost to D3.
- **Triage as a workflow stage.** Saved workflows cannot consult the operator mid-run; the scout can be a subagent, the round cannot. Lost.
- **Deterministic denylist tiers** (four council lenses). Premature mechanization of a judgement LLMs make well; policy as rules first, code after a measured miss (D5).
- **Intake in the `genie` skill** (this design's first cut). Superseded by "it is the canonical wish": the procedure lives in `wish`; `genie` routes to it.
- **`work` as a separate manual procedure for Standard wishes.** Two procedures drift and the majority path never gets the workflow. Lost to D9.
- **`.genie/wishes/<slug>/WISH.md` at capture.** Fails `wishes:lint` inside `bun run check` and needs a new status. Lost to D2.

## Simplicity Case

- **Simplest complete design:** one procedure in one skill, one read-only scout, one config key, `wish.js` with two optional args, one rules file; every other verb is one handoff line.
- **Added machinery:** derived WRS (a self-declared bar is checklist theater — council, domain-map draft); `groups[]` in the contract (one PR for the 92% of wishes with more than one group); the concurrency cap (unbounded fan-out otherwise); the capture gate — credential scan, size bound, URL + digest, explicit publish (public `.genie/`); one bounded review round for Standard/Program contracts (plan review caught real defects in observe-skill-bundle rounds 1–3); the rules file (policy without code); the two hold kinds — `holdBeforeWork` (v6's refusal kept for paths that execute at the executor's commit; the manual body delivers them) and `holdBeforePublish` with `readHead` (a human read of the exact SHA before LLM-written code executes on CI; the release rerun costs a second admit, an adopt-only executor pass that writes nothing, and a second gate and review pass).
- **Deferred until measured:** mechanized tiers (trigger: a misjudged boundary in a measured run); scout reuse between triage and admit (trigger: double-scout cost dominating three runs); parallel groups inside one wish (trigger: sequential group time dominating three Standard runs); Orca dispatch (trigger: a DSH/Orca workflow executor); removing the D6 review round (trigger: it changes no contract in three Standard runs); dollar appetites (trigger: per-lane p50/p90 from measured runs).
- **Complexity removed:** the authoring judge; `units` as a refuser; the refusal exit; orchestrator-authored objectives; four-round plan review for single-task wishes; the router's fourteen-row table; deterministic tiers; per-slice admission and publish overhead.

## Decisions

| # | Decision | Rationale |
|---|----------|-----------|
| 1 | The WRS returns as the triage instrument; skills are the manual system and stay complete by hand, workflows automate the same procedure | Its removal in `ed6028f15` was collateral of the consolidation ("i never asked deletion… i thought the old manual skill system would stay") |
| 2 | Same filesystem, more automation: DRAFT.md at capture, WISH.md at freeze with optional extra sections, no new status | Keeps `bun run check` green, doctor's Raw→Idea mapping and `dream`'s exact-APPROVED selection intact; "the user has to worry less and less, only when it matters the most" |
| 3 | One wish = one task done; in code, one PR; groups sequential in one worktree; a program is sibling wishes | Admission once, publish once, one merge, no stacked bases; dissolves the council's per-slice objection |
| 4 | One explicit "go" on every wish, even at WRS 100; mandatory for issue or pasted intents | Zero questions is the win; zero approval is an attacker-authored-issue path v6 never had |
| 5 | Boundaries are policy in `.claude/rules/`, judged by LLMs; mechanize only after a measured miss | "dont turn it deterministic before we prove value, llms are smart" |
| 6 | One bounded review round (cap 1) for Standard and Program contracts; Patch and Small skip it; measured over three runs | Reconciles the defects plan review caught with the round-trip target (delegated to the session) |
| 7 | Sequence: slice 0 → `observe-skill-bundle` via `work` → skills-restore → slice 1 | Proof of value needs per-turn USD and call measurement; that tooling is APPROVED and touches no slice-0 file (delegated to the session) |
| 8 | Any wish can be asked; triage decides depth; Freestyle lane for non-code outcomes | "we shouldnt lose software depth because of it" |
| 9 | Every lifecycle verb that mutates or plans is a front door to the canonical wish, verb as type hint, by-hand procedure kept; assess-only verbs hand off without capturing; the `quick` stub is untouched | "people dont know it changed, it just route to the same dynamic new mode" |
| 10 | Parallelism across wishes, never inside one; batch → N scouts → one round → one "go" → N runs; overlap sequenced; `budgets.maxParallelWishes` | "one orchestrator may orchestrate multiple simultaneous wishes workflows in parallel" |
| 11 | The procedure lives in the `wish` skill; `brainstorm` keeps the deep path; `genie` routes | "its gonna be the canonical wish and thats it" |
| 12 | The eleven deleted skills and the lenses return as front doors and reference material | Confirmed; they are the software depth D8 refuses to lose |
| 13 | The WRS is derived from checkable evidence per dimension; the scorer is not the agent that proposed the file set | Gaming resistance without an independent scorer's cost |
| 14 | Card and timeline writes stay with the session between runs; `FORBIDDEN_GENIE_VERBS` stays in every workflow brief | The script's "no IO" header stays true; Orca mode refuses local card writes |

## Risks & Assumptions

| # | Risk | Severity | Mitigation |
|---|------|----------|------------|
| 1 | Verbatim intent in public git is a PII or stored-injection surface for every later reader, including overnight `dream` | High | Credential scan, size bound, issue as URL + digest, explicit "publish this" for pasted text, fence header on the persisted intent, `injectionAttempts` shown in the round |
| 2 | An acknowledged path carries LLM-written code into execution before a human reads it — `.github/` on PR open with a repository secret; hooks and lint configs at the executor's own commit | High | Acknowledgement per path in the operator's own words; execute-at-commit paths stay refused for the automated body (`holdBeforeWork`) and are delivered by hand; `.github/` is held before any push and released only against the SHA the operator read (`readHead`, script-checked at release and at read-back); any unacknowledged hit still refuses or blocks at every consult point; the PR body names every acknowledgement for the merger; the first live acknowledged run rehearses the hold, the read and the release on a dummy `.github/` file before any real workflow edit. A judgement miss on the policy text is untestable by construction — that is exactly what the mechanization trigger watches: one misjudged hold mechanizes that entry |
| 3 | A self-scored WRS unlocks delivery on a hollow contract | Medium | Derived WRS (D13); the "go" is never dropped (D4) |
| 4 | A four-group wish becomes one long run and a late failure loses the earlier groups | Medium | Commit per group; resume adopts the clean worktree (v6 rule); `## Attempts` names the group reached |
| 5 | Parallel wishes collide on shared files or exhaust the host | Medium | Declared-set overlap → `depends-on`. The shared `.genie/genie.db` sees only the session's writes: workflow agents never write cards (D14) and the pre-commit `task sync` is skipped in linked worktrees (`.husky/pre-commit:23-27`). `budgets.maxParallelWishes` bounds host contention — N `git worktree add` on one common dir, N × `bun install` and `bun run check` — and its default is set from the first measured parallel run |
| 6 | The double scout (triage + admit) costs more than the judge it replaces | Low | Measured over three runs; reuse deferred with a named trigger; the ⊆ bound needs the script's own scout |
| 7 | Slice 1 rewrites pinned surfaces: `skills/wish/SKILL.md` ≤95 lines with the state and route enums, the band sentence, the by-hand stage order and the inherited clauses pinned (`scripts/wish-workflow-parity.test.ts:47-105, :169-172`) and phrases pinned (`scripts/release-docs.test.ts:971-973, :1079`); the saved-name and no-roster clauses (parity `:40-45`) and the scaffold fence (`scripts/fresh-install-smoke.ts:238-253`); the `genie` router table's header and cells (`release-docs.test.ts:977, :1060-1067`); slice 2 additionally meets the `wish.js` pins — nine model spreads (`scripts/wish-workflow-parity.test.ts:157-159`), the SCOUT and GATE required lists (`:162-164`) and the fence (`:166-168`) | Low | Each pin is updated in the same PR as the surface it pins, with its test, and the by-hand section stays complete; the `quick` stub, pinned byte-exact (`wish-workflow-parity.test.ts:118-122`, `release-docs.test.ts:974, :982`), is not touched |
| 8 | `bun run check` red from a capture-time WISH.md | Low | No WISH.md before freeze (D2), by construction |
| 9 | Orca mode: `wish.js` cannot be an Orca dispatch and capture cannot write a card | Medium | `work` keeps its Orca protocol; card creation skipped with a note; `wish.js` in Orca mode deferred |
| 10 | Restoring eleven skills bloats the catalog or fails the skills lint | Low | Each re-linted with the handoff line; a `skill-audit` pass afterwards |
| 11 | The 60/100 thresholds and the bands are brainstorm-era numbers reused for routing | Medium | Advisory until the three-run calibration window closes; recorded per run |
| 12 | The operator abandons a round mid-way and no artifact is written | Low | The session writes DRAFT.md and the card at capture, before any question; Triage is written on every exit path |
| 13 | `observe-skill-bundle` and this program touch the skills catalog and `scripts/release-docs.test.ts` | Low | D7 ordering recorded in both WISH.md files |
| 14 | Business-language wishes get software ceremony, or software wishes get Freestyle | Medium | Freestyle only when triage finds no repository or no code outcome; the operator sees the lane in the one chat line and can override it in the round |

## Success Criteria

- [ ] Slice 0: a behavior test proves a declared `scripts/release-docs.test.ts` no longer hits the denylist; an estimate of 9 units with files and insertions inside the band routes `proceed`; the README measured-runs table holds runs 2–5 with USD and API-call columns.
- [ ] Capture: after `/wish <sentence>`, `.genie/brainstorms/<slug>/DRAFT.md` holds `## Intent` equal to the sentence byte-for-byte under the data header, `genie task list` shows a card with `tasks.wish = <slug>`, and `bun run check` is green with only that DRAFT.md present.
- [ ] Triage: the operator's run-4 intent, verbatim from the handoff — "lets fix the gaps, make workable for anyone that use phoenix locally, theres no need to document other than a readme on the workflow folder itself, its useful to have that bundled, so that any genie user that also uses phoenix can use it" — yields one round of at most five items, lane Small, a derived WRS with a test per dimension, and `rounds: 1` in `## Triage`; no run starts without a recorded "go".
- [ ] Contract: the WISH.md scaffolded at freeze passes `wishes:lint` with `## Intent`, `## Triage` and `## Attempts` present.
- [ ] Delivery: a `wish.js` run with `contract.groups` of length two yields one worktree, one branch, one PR, two focused verdicts and one integrated verdict in the report; the parity and behavior tests prove `merge-ready` read-back equality unchanged and an `objective`-only run still admits through the authoring judge.
- [ ] Boundaries (fake-agent behavior tests with a fake judge returning the hold, so the script's plumbing is what is proved): a declared path under `.github/` with no acknowledgement refuses at admit, blocks at review and mismatches at read-back; with an acknowledgement the run ends `blocked` before any push naming the head SHA; a rerun whose `readHead` differs from the head the adopt-only executor reports holds again, one whose worktree is dirty fails adoption and ends `blocked` with the diagnostic and nothing pushed, and one whose `readHead` equals the reported head re-gates, re-reviews and publishes with the acknowledgement recorded in `## Triage` and rendered in the report and the PR body, read-back asserting `pr.headOid === readHead`; an acknowledged `.husky/` path is `refused` with route `plan` and nothing is created.
- [ ] Parallel: two issues yield two background runs, two worktrees, two PRs; two wishes with intersecting declared sets are sequenced; `genie config get budgets.maxParallelWishes` reports the default and a value over the ceiling fails the parse.
- [ ] Front doors: every lifecycle SKILL.md except the `quick` stub opens with the handoff line, the assess-only verbs with its no-capture variant (parity test); the eleven restored skills and the lenses pass `bun run skills:lint` plus a 40–90 line-count assertion the lint does not enforce.
- [ ] Measurement: three v7 runs are recorded with rounds, WRS at freeze, lane, estimate vs real diff, USD and calls; the offline replay over `wishes.csv` is published beside the 68% figure.
- [ ] This design carries SHIP evidence with a verified digest before any WISH.md of this program is written.
