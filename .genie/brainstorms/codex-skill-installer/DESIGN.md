# Design: Skills via skills.sh + CLI everywhere — plugins only for Orca

| Field | Value |
|-------|-------|
| **Slug** | `codex-skill-installer` |
| **Date** | 2026-08-30 (rev. 6 after five FIX-FIRST design review rounds) |
| **WRS** | 100/100 |
| **Base branch** | `dev` (this brainstorm was written on `v6/corpo-leve`, 2 commits ahead of an older `dev`; the Orca plugin named below exists on `dev`/`main`, not on this branch — see Risk 12) |

## Problem

Genie's value inside any agent session is its skill set plus the `genie` CLI, yet every agent gets a bespoke delivery subsystem — Codex plugin (authenticated delivery, TTY-only activation, generations, fallback lanes, repair/rollback, 4-platform release dogfood), Claude marketplace plugin (hooks, role agents, council stamp, LENS_ROOT stamping), Hermes/pi plugin links. Measured on a clean `git archive origin/dev` (2026-08-30): non-test code matching `codex-*|*plugin*|agent-sync*|runtime-integrations*|src/hooks/*|*dogfood*|hook-*|council-workflow*` = **42 files / 27,248 lines** (`agent-sync.ts` 7,458; `runtime-integrations.ts` 4,219; `codex-activation.ts` 2,158; `codex-lifecycle-lease.ts` 1,068; `codex-project-mcp.ts` 1,028), **80 files / 48,616 lines** with tests, plus `plugins/` 158 files. Dogfooding stable v5.260830.16 still needed a manual interactive Codex activation and surfaced a doctor false positive in the stamp logic (PR #2864). skills.sh already installs the repo's top-level skills into every detected agent with one command and zero repo changes (`npx skills add automagik-dev/genie@v5.260830.16 --list` → "Found 22 skills"; same count on `@dev` and `@v6/corpo-leve`).

## Scope

### IN
- **Contract: everywhere except Orca, Genie = skills + CLI. Nothing else is delivered to any agent.** This supersedes the "rehome supported hooks and role templates with parity fixtures" clause of `genie-dual-mode-orca-plugin/DESIGN.md`; both `genie-dual-mode-orca-plugin/DESIGN.md` and its live `WISH.md` (IN_PROGRESS on `dev`, A1–A7 merged, dev→main promotion mid-flight) get the same amendment note in Wish A; its MCP-retirement ownership is unchanged, but since `src/term-commands/mcp.ts` and `src/lib/codex-project-mcp.ts` still exist on `dev` after A7, Wish B must not touch them and Risk 15 sequences B behind that promotion.
- **Skills inventory = `skills/*/SKILL.md` top-level directories** (what skills.sh discovers by default). The v6 nested `skills/genie-orca/{wish,work,review}/SKILL.md` are invisible to the CLI and, with `--full-depth`, collide with the top-level `wish`/`work`/`review` names — they move to top-level, uniquely named dirs (`skills/orca-wish`, `skills/orca-work`, `skills/orca-review`) when that branch lands. The untracked `skills/quick` on v6 is fixed there. Criteria assert against the inventory file list of the release tag, never a literal count. Sequencing: `v6/corpo-leve` (2 ahead / 55 behind `dev`; forward content = `skills/genie-orca/*` + `.genie` docs) is merged into `dev` **before Wish B** with the genie-orca skills already moved to their top-level names as part of that merge; Wish C then only lints and documents them. Wish B never runs while v6 is unmerged (Risk 12).

## Scope size

Too large for one wish (H6). Three sequenced wishes under this design; each independently reviewable, each leaves `bun run check` green:

1. **Wish A — additive channel + retirement (no deletions):** `skills-installer.ts`, install record, `legacy-integration-retirement.ts` wired into `genie update`, doctor skills surface, `skills-install-smoke` + `release-update-path-smoke` jobs (added alongside the old matrix), lease/atomic-fs rehome, dual-mode design amendment note. Ships first so real hosts are migrated **while the code that produced their assets still exists**.
2. **Wish B — subtractive:** delete Codex/Claude/Hermes/pi plugin code, `src/hooks/*`, `agent-sync.ts`, `plugins/genie` non-Orca files (Codex, Claude, Kimi, hooks, agents, scripts, skills mirror), the old dogfood matrix/harness/validator, `check` script surgery, the build/release toolchain group (C11), uninstall rewrite. Pre-condition: Wish A released as stable and one dogfood host migrated (C3).
3. **Wish C — skills + docs:** genie-orca skills to top-level unique names (with the v6 branch), skills-lint tokens, `work` skill wording, CLAUDE.md/AGENTS.md/docs rewrite, release notes for the accepted behavior changes.

## Approach

**A (chosen): skills.sh + CLI; every non-Orca integration deleted.**
`genie install`/`update` = (1) verify/promote the signed binary as today (lease from `lifecycle-lease.ts`), (2) run the pinned `npx skills add … --all --copy`, write the install record, (3) run the marker-scoped retirement, (4) Orca plugin unchanged. `genie uninstall` = inventory-dir deletion from recorded agent dirs + binary removal. `genie doctor` = binary + inventory vs. present agent homes + Orca ref.

Alternatives considered:
- **B — skills.sh for skills; keep hooks/role agents delivered by genie (rev. 1 draft).** Honest cost: low — `~/.codex/hooks.json` is already a live global surface and role agents are already plugin-independent, so the rehome would be a small marker-owned writer. It lost on user direction ("skills + cli, nothing else"), not on cost; the reversal cost if a hook is ever needed again is correspondingly small (Simplicity Case, deferred).
- **C — genie copies skills from its signed tarball; skills.sh as a public alternative.** Two channels, keeps digest/manifest machinery. Lost: one-channel decision.

Design for isolation: `src/lib/skills-installer.ts` (pure argv builder + record reader/writer + `run` with injected spawner; tested with a fake `npx` shim); `src/lib/legacy-integration-retirement.ts` (one marker-scoped classifier + backup-first remover per legacy surface, each tested with a tmp home); `src/lib/lifecycle-lease.ts` and `src/lib/atomic-fs.ts` (moved, not rewritten; existing tests move with them); Orca code untouched.

## Simplicity Case

- **Simplest complete design:** one pinned `npx skills add` + signed binary + one-time retirement. No per-agent writers, no hooks, no stamps, no generations.
- **Added machinery:** `~/.genie/skills-install.json` — pays for doctor freshness and idempotent `update`; `legacy-integration-retirement.ts` — pays for hosts that already carry the plugins (time-boxed: deleted two stable releases after Wish B); `release-update-path-smoke` — pays for the previous-stable→candidate proof the old matrix carried.
- **Deferred until measured:** project-scoped installs — on reported global/project conflicts; skill signing — if skills.sh grows verification or tag trust is shown insufficient; per-platform smoke matrix — if the single smoke misses a platform-specific failure; re-adding any hook (cheap: global hooks files already exist) — only with a concrete incident a skill cannot prevent; a distinct bot identity for agent merges — only if an agent ever merges to `main` after Wish B.
- **Complexity removed:** Codex plugin (activation, generations, fallback lanes, repair/rollback, hooks, role profiles, dogfood harness/validator), Claude plugin (marketplace, hooks, role agents, council stamp, LENS_ROOT), Hermes/pi links, `agent-sync.ts` (7,458 lines minus the ~300 rehomed), `runtime-integrations.ts` plugin paths, six `check` lints, interactive-TTY requirements, ~15 doctor checks.

## Decisions

| # | Decision | Rationale |
|---|----------|-----------|
| 1 | skills.sh is THE skills channel; genie wraps `npx skills add automagik-dev/genie@v<ver> --all --copy` | User pick. Repo already compatible; release-tag pin gives immutable content; one code path. |
| 2 | Everywhere except Orca: skills + CLI only — no hooks, role agents, workflows, or per-agent links | User direction 2026-08-30: "plugin is shitty to maintain. skills sh + cli for the win everywhere, except orca". Supersedes the dual-mode rehome clause. |
| 3 | Delete Codex, Claude, Kimi, Hermes, pi integrations, all six hook handlers and `agent-sync`; keep only the Orca plugin | Follows from 2; dormant lanes still cost tests, doctor surface and security review ("deprecate loudly, remove decisively"). |
| 4 | Global scope, `--copy`, `--all`; the release smoke runs the identical argv | `--copy` yields plain files; `--all` matches "installs to all detected agents in a blink"; gate must exercise production argv. |
| 5 | Two single-platform smokes (`skills-install`, `release-update-path`) replace the 4-platform Codex matrix; musl covered through the retained adapter | Skills are platform-independent files; the update path is the part that bit us before and stays exercised, not just attested. |
| 6 | Pin and record the skills CLI version | skills.sh moves fast (`experimental_*`); pinned + tested keeps `genie update` deterministic; bump via dependency PRs. |
| 7 | Skills must be self-contained and name no plugin-only agents | skills.sh copies skill directories only; the lint tokens are the forms the skills actually use today (`genie_engineer_*`, `engineer-trivial`, …). |
| 8 | Migration is marker-scoped, backup-first, time-boxed; unmarked assets reported, never removed | Same safety contract the repo enforces for `.codex/config.toml` routes. |
| 9 | Three sequenced wishes, additive before subtractive | Retirement must be proven on real hosts before the code that produced their assets is deleted. |
| 10 | Lease and atomic-fs primitives are moved, not rewritten | They guard install concurrency and no-clobber publishes; unrelated to per-agent delivery. |
