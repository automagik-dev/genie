# Council record — wish-v6 design (run wf_f4a43c6d-b1f, 2026-09-16, 6 agents, 620k subagent tokens, 6.7 min)

# Council: Adopt the genie V6 design in .genie/brainstorms/wish-v6/DESIGN.md: `/wish` becomes one saved workflow (`.claude/workflows/wish.js`) that delivers ONE task end to end — Admit (read-only scout + blind judge deciding route proceed|report|brainstorm|plan by sufficiency and by the study's size thresholds) → one executor in one worktree → mechanical gate (bun run check) → blind independent review → bounded repair → publish PR to dev and read the remote back → state merge-ready|refused|blocked|missed with its own token bill. The `wish` skill becomes the front door (council pattern), `quick` is deleted, merge stays with the operator. It is the proof of concept that the whole genie framework can be represented by a single workflow, with every other skill auxiliary. First dogfood target: open issue #2921.

## Lenses
### architecture
Verdict: support-with-conditions
Confidence: medium
Key evidence:
- The study's size-duration relationship is real on the only proxy that measures delivery: PR-branch hours vs wish lines rho 0.67, PR insertions 0.70 (n=50, v4+v5); <=150-line wishes merged 100% within 8h, >400-line wishes 30% (WISH-DURATION-STUDY.md section 5). Admission-by-size has an evidentiary basis; admission-by-clock (quick/SKILL.md 'Admission (minute 0-5)', 'Record the start time') has none, and the catalog forbids clocks anyway (scripts/workflows-meta.test.ts:13-15 bans Date.now, argless new Date).
- The catalog contract the design targets is enforced and precedented: scripts/workflows-meta.test.ts checks pure-literal meta, forbidden tokens (process/fs/child_process/fetch/timers/absolute paths) and parses the body against exactly the globals agent, parallel, pipeline, phase, log, workflow, budget, args (:56); council.js + skills/council/SKILL.md + scripts/council-workflow-parity.test.ts already pair a skill and a workflow by name, so decision 1 is not new coupling.
- The bounded-repair shape the design copies is already in the catalog: workfly.js:334-349 loops while blocking.length && repairs < maxRepairs, spends no round on a null repairer, and computes ok only when every lens ran (:351-357). Reusing this idiom keeps the new script inside the shape the two refuters already know how to verify.
- The hook floor the design leans on exists client-side and server-side: .husky/pre-push refuses refs/heads/(main|master) and runs bun run check:fast; .husky/pre-commit blocks commits on a red CI branch (SKIP_CI_CHECK=1 override) and skips genie task sync in linked worktrees (git-dir != git-common-dir); .claude/hooks/git-safety.sh exits 2 on --no-verify and on bare --force. AGENTS.md line 42 states merge-to-dev is operator policy with no client-side guard, which is exactly why 'merge-ready' rather than 'shipped' is the correct terminal state.
- The worktree convention is real and gitignored: .gitignore:66-67 ignores .claude/worktrees/, and git worktree list shows two live ones (fix-skill-leftovers, genie-v6-workflow). Decision 7 (real worktree, not isolation:'worktree') is correct because the authoring reference says an isolation worktree 'is auto-removed if unchanged' and is meant for parallel mutators, while the branch here must outlive the agent for push and PR.
- Contract mismatch on the token bill: the workflow-authoring reference defines budget.spent() as 'output tokens spent this turn across the main loop and all workflows — the pool is shared, not per-workflow', and budget.total as a HARD ceiling after which 'further agent() calls throw'. DESIGN.md IN bullet 1 and the success criterion ('subagent tokens below ... 316k') assume a per-run, all-token bill that this API does not provide; the README's measured-runs column is 'Subagent tokens' from the run record, not budget.spent().
- Injection cost per agent is ~57k chars (CLAUDE.md 48,509 + AGENTS.md 6,630 + ~/.claude/CLAUDE.md 1,894 bytes), roughly 14k tokens before any work. Seven happy-path agents (DESIGN.md Approach) start ~100k tokens deep; the cheapest recorded run (research-sweep, 5 read-only readers, 316k, README Measured runs) had no executor, no bun run check output and no diff to read. The 'below 316k' criterion is a stretch target, not a plausible first-run outcome.
- The result enum has no slot for the state the design itself expects: Risk 3 says unconcluded CI is 'reported as pending; the front door tells the operator to re-read', but the terminal states are merge-ready | refused | blocked | missed and 'Any mismatch is blocked, never merge-ready'. Observed CI wall clock on dev/PR runs today is 3-5 minutes (gh run list: 19:20:55->19:24:09, 19:08:02->19:11:25, 18:40:04->18:43:04), so a bounded watch inside one agent call is feasible, but the contract still needs a named 'pr-open, checks pending' outcome.
- The change's own file set exceeds the maximum band the design sets: DESIGN.md IN names wish.js, skills/wish/SKILL.md, skills/quick (delete), skills/genie/SKILL.md, skills/genie/reference/lifecycle.md (grep: :35 names quick), skills/README.md:76, scripts/release-docs.test.ts (:26, :963-979 pin quick strings), .claude/workflows/README.md, scripts/wish-workflow-parity.test.ts = 9, plus the evidence directory already holding 778 lines across 4 files (wc -l .genie/brainstorms/wish-v6/*) and two more promised (TIMELINE.md, council record) = 15 files. Insertions land inside 2,000; the 12-file ceiling does not.
- The design's own gate is unstamped: DESIGN.md 'Design Review Evidence' reads Verdict PENDING / SHA-256 PENDING, and skills/wish/SKILL.md 'Design preflight' says a missing or non-SHIP digest 'cannot be waived'. The workflow's Admit stage does not mention this preflight, so single-task objectives that came through brainstorm would lose the one stamped gate the lifecycle has (FRAMEWORK-BRIEF.md section 1, Explore row).
- Prompt duplication is the long-term cost: the executor rules (stage by path, declared set), blind-criteria rule (skills/review/SKILL.md 'Blind criteria first'), repair budget semantics (skills/fix/SKILL.md 'Repair budget', B from genie config get budgets.maxEscalationsPerGroup) and delivery evidence rule (skills/work/SKILL.md Delivery) will be restated inside wish.js prompts. Subagents receive CLAUDE.md, not skills, so those clauses become a second copy with no parity test between wish.js and review/fix/work.
Risks or objections:
- budget.total is a hard ceiling that makes agent() throw: an operator '+Nk' directive can kill the run between push and read-back, leaving a pushed branch and possibly an open PR with no 'missed' result unless every stage is wrapped in try/catch that returns state:'missed' with the preserved artifacts.
- Token target likely missed on run one: ~14k injected tokens x 7 agents plus a code-editing executor, a bun run check transcript and a diff-reading reviewer will not fit under the 316k a five-reader research sweep cost; if the criterion is treated as a gate the POC fails on cost, not on design.
- Two-meaning skill: 'wish' becomes both 'deliver one task' and, via a refusal, 'write a multi-group WISH.md'. An operator who already knows a multi-group plan is needed has to pay two admission agents (~30k tokens) to be refused into the plan section; the genie router row 'Defined work needing a durable plan -> wish -> work once APPROVED' becomes true only through that refusal.
- Orphaned worktrees and branches: nothing in DESIGN.md names who removes .claude/worktrees/wish-<slug> after merge-ready, refused-after-worktree-creation, or missed; the dogfood host already carries two. Risk 5 only covers a pre-existing worktree name, not a pre-existing remote branch (git push -u to it fails non-fast-forward, which should classify as blocked).
- Front-door parity by 'normalized verbatim equality' between a shipped SKILL.md and a repo-local script pulls repo facts (gh pr create --base dev, bun run check, the six #2926 darwin names) into a skill delivered to every agent home — the exact leak #2916/#2917 describe. The by-hand fallback for a seven-stage delivery pipeline is also the whole procedure in prose, which is the old quick+work text under a new name.
- Board invisibility: a V6 run creates no roadmap card and no tasks.wish slug, while CLAUDE.md declares the roadmap board the one tracker; the only trace of a delivered task is the catalog's measured-runs row and the PR. quick had the same gap, but the design makes this the primary delivery path.
- Resume replays cached agent() results: a resumed run whose worktree or branch was pruned in between will replay the executor's 'committed' result and fail downstream in ways the journal, not the result, explains.
- The hardcoded darwin allowlist (six test names from #2926) becomes stale the day the issue closes or a seventh darwin failure appears; a stale allowlist is harmless but a new darwin-only failure turns every local gate red while ubuntu CI is green, so the read-back must remain the authority and the local gate must not be allowed to end the run as blocked on darwin-only names.
- skills/wish/SKILL.md frontmatter is category: lifecycle, mutates: documents; the V6 wish pushes branches and opens PRs, so the frontmatter and skills/README.md catalog row must change to mutates: repo or the catalog lies about side effects.
Required conditions:
- Replace 'budget.spent()' in the result contract with what the runtime can actually report: either read the per-run subagent token count from the run record after the workflow returns (as the README measured-runs table does today) or return budget.spent() labelled explicitly as shared-turn output tokens; the 316k comparison must be recorded as a measured target for calibration, not a pass/fail success criterion for the first dogfood.
- Wrap every agent() call (or each phase) so a budget-ceiling throw or a null agent returns state:'missed' with branch, head, PR (if any) and the stage reached; the run must never end by exception after a push.
- Add a result field checks: 'pass'|'fail'|'pending' and a named outcome for 'PR open, checks pending' (do not overload blocked or merge-ready); bound the read-back to one gh pr checks --watch under gtimeout (CI observed 3-5 min) and state in the front door that pending is re-read by the operator.
- Admit must run the existing design preflight: when .genie/brainstorms/<slug>/DESIGN.md exists, the scout reports the design-review evidence verdict and digest state and the judge refuses to brainstorm on a non-SHIP or mismatched digest; stamp this DESIGN.md's own review evidence before the dogfood run.
- Give the front door a direct entry to the plan section that skips the admission agents when the operator already declares a multi-group objective; the refused plan route is the automatic path, not the only one.
- Name the worktree/branch lifecycle: the executor refuses (blocked) when the local worktree path OR the remote branch already exists; the result names the worktree path; cleanup after merge is the operator's and is stated in the front door.
- Pin shared clauses to the skills they copy: the parity test should compare wish.js prompt clauses for blind criteria, repair budget and delivery evidence against skills/review, skills/fix and skills/work text (normalized equality), and the shipped SKILL.md must carry no repo-local command strings or darwin test names (AGENTS.md line 33, #2917).
- Land the evidence directory (TIMELINE, study, csv, brief, council record) in its own docs-only PR or accept in writing that the delivery PR breaches the 12-file ceiling; the code+skill change alone (9 files) stays inside the band.
- Update skills/wish frontmatter to mutates: repo and the skills/README.md and lifecycle.md rows in the same change; release-docs.test.ts assertions at :26, :963-979 and :1009-1083 must be rewritten rather than deleted so the new front door keeps pinned wording.
- Consider folding the criteria writer into the judge: the judge's frozen contract (core, cuttable, oracle, declared file set) is written before any code exists and is therefore blinder than a post-hoc criteria call; this removes one ~14k-token injection and answers unknown #2 without merging scout and judge.
Unknowns:
- Whether the runtime exposes a per-run subagent token total that a script can read before returning; the authoring reference documents only the shared-turn output pool, so the measured-runs number may only be obtainable after the run from /workflows or the journal.
- Whether the scout's pre-code estimate of files/insertions/units tracks the real diff: the study correlates wish document size with branch hours, not an agent's a-priori estimate; the calibration loop (estimate next to real diff in the result) is the right instrument but has zero data points today.
- What text the 'normalized verbatim equality' parity test will pin between SKILL.md and wish.js; if it is the route/state enums and the by-hand stage list it is safe, if it is command recipes it re-creates #2917.
- Whether a fresh worktree's bun install --frozen-lockfile plus bun run check plus the pre-push check:fast (typecheck, biome, knip, four lints) fits the wall-clock budget the study implies for the ideal band (<=1h branch time) when repair rounds re-gate; no measured run of a code-mutating workflow exists in the catalog.
- Whether #2921 is still the right first dogfood target after this design lands: its section 1 fix is in the author prompt of workfly.js and its section 2 model-default fix touches four scripts (workfly, skill-audit-sweep, docs-audit, research-sweep), which may exceed the single-script scope the design describes.

### product
Verdict: support-with-conditions
Confidence: medium
Key evidence:

Deleting it removes a promise no host can keep.
- The proposed shape already exists in the catalog: skills/council/SKILL.md fronts .claude/workflows/council.js with no roster of its own, scripts/council-workflow-parity.test.ts pins the pairing, workfly.js:334-349 holds the bounded repair loop, and .claude/workflows/README.md records five measured runs.
