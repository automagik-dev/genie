## Problem

The approved `genie-launch` design promises one card image per core skill in the genie README (group C) and a docs skills catalog, but no card exists, and its plan made them in a throwaway scratchpad pipeline that nothing keeps true when a skill's own text changes. This work replaces that step with a tracked generator that builds every skill card image from the skill's own `agents/openai.yaml`, so the six README cards and the 18 docs cards say what the skills say, and a text test catches a README card that drifts.

## Approach

A single Bun script, `scripts/skill-card-images.ts`, writes each card as an SVG string. For a skill it parses `skills/<name>/agents/openai.yaml` with `Bun.YAML.parse` (the parser `scripts/release-docs.test.ts` already uses) and emits, on a `viewBox="0 0 800 400"` canvas: the design B surface `#0B0B12` with a `#2A2438` border; the `display_name` as the title and the `short_description` as one or two lines, both in Geist with `#E8E6F0` text; `/name` and `$name` in JetBrains Mono on the magenta `#FF3FF5` and cyan `#5EF2FF` accents, with the glow (`feGaussianBlur`) on accents only; and the official logo as a small corner mark. The two fonts sit in an `@font-face` block as base64 `data:` URIs and the logo as a PNG `data:` URI, because GitHub and Mintlify show SVG through `<img>`, which fetches nothing external. Each `font-family` names a system face after the design B one, so a platform that does not draw the embedded fonts still draws text: title and line use `Geist, system-ui, -apple-system, 'Segoe UI', Helvetica, Arial, sans-serif`, and the commands use `'JetBrains Mono', ui-monospace, SFMono-Regular, Menlo, Consolas, monospace`. The design B values live as constants in the script with a comment citing `GENIE-DESIGN-TOKENS.md`, since that file is gitignored.

Every name, line and command stays a `<text>` node, never outlines, which is what lets the R2-2 test read them. Every value from the YAML is XML-escaped (`&`, `<`, `>`, `"`, `'`) before it enters the SVG. The line wraps at a space into at most two `<text>` lines of up to 34 characters each, at the space that makes the longer of the two lines shortest (a tie goes to the earlier space, so the output stays byte-stable), so no card ends on a one-word second line (greedy wrapping would leave `design`, `evidence` and `retries` alone on brainstorm, work and fix); a `short_description` longer than 68 characters, or one that would need three lines, and a `display_name` longer than 24 characters are refused with exit 1 and nothing written. Today every value fits (titles 3 to 22 characters, lines 36 to 63).

The six core skills are a constant in the script: `brainstorm`, `wish`, `work`, `review`, `council`, `fix`. With no flag the script writes `.github/assets/skill-<name>.svg` for those six. With `--docs` it writes `docs/images/skills/<name>.svg` (through the `docs` symlink into the submodule, `genie/images/skills/` in automagik-dev/docs) for every `skills/*/` directory with a `SKILL.md`, the 18 that `SHIPPED_SKILLS` pins; when `docs/` does not resolve, because the submodule is not initialized, it exits 1 with a clear message and creates nothing. `--check` regenerates in memory and compares byte for byte with the committed files, exits 0 when they match and 1 naming each file that differs; with `--docs` it also compares the 18, for local use. The script exports both the check and the write path, `--docs` included, as functions over a given repository root, and the command line passes the real root. The test runs the check against the real tree and against a temporary copy with a changed `short_description` or `display_name`, and runs the `--docs` refusal against a temporary root whose `docs` symlink dangles, so no test ever writes into the real tree or the CI-checked-out submodule.

The render check comes first. Before the other cards are built, the generator produces one card (`brainstorm`), and that card is viewed through `<img>` in the same context each placement owner will use, to confirm that the embedded fonts, the logo `data:` URI and the glow render. Viewing the SVG file's own GitHub page or its raw URL does not count, because neither is an `<img>` embed. On GitHub: a throwaway genie branch, never merged and never the base of the genie PR, holds the card at `.github/assets/skill-brainstorm.svg` and a scratch `render-check.md` at the repository root that embeds it with the README-relative `<img src=".github/assets/skill-brainstorm.svg" width="400">`, the way group A will in the README, and the check reads that file's rendered view on github.com. On Mintlify: a throwaway automagik-dev/docs branch, separate from the docs PR, holds the card at `genie/images/skills/brainstorm.svg` and a temporary page `genie/render-check.mdx` that embeds it with `<img src="/genie/images/skills/brainstorm.svg" />`, the way group B will in the "4. Skills catalog" page; the check reads that page in the branch's Mintlify preview, opening a draft PR that is closed unmerged if the preview needs one. Both throwaway branches are deleted once the genie PR merges, and neither the scratch file, the temporary page nor any commit of theirs reaches the genie PR, the 18-file docs PR or docs `main`. The outcome follows R5-1. If only the embedded fonts fail on a platform, the cards ship anyway and that platform draws them in the system stacks above: the text stays text and readable, without the design B typeface there. If the logo or the glow fails on either platform, the work stops after this first card and goes back to the owner; outlines and raster cards stay ruled out by R2-1. The genie PR body links the GitHub view and the Mintlify preview, attaches a screenshot of each so the record outlives the deleted branches, states per platform whether fonts, logo and glow rendered, and names a font-only failure as the R5-1 fallback.

Delivery runs in three PRs: a genie PR to `dev` with the generator, fonts, license, logo, the six SVGs, the test and the `genie-launch` tracking, amendment and re-stamp of IN #7 and IN #8; a PR to automagik-dev/docs with exactly the 18 SVGs under `genie/images/skills/`; and, only after that docs PR merges, a separate genie PR that bumps `.docs-vendor`.

Alternatives considered:
- **The `genie-launch` throwaway pipeline** (HTML frames, Chromium, ffmpeg in the scratchpad): lost to R1-4; nothing would regenerate a card or notice when a skill's text changes.
- **Generating in the release pipeline:** lost to R1-1; the release workflows run the `main` copy and are the most guarded files in the repository, for images that change rarely.
- **PNG rendered through a headless browser:** lost to R2-1; it adds a browser and a binary per platform, its bytes are not stable across hosts, and a test cannot read its text.
- **The `SKILL.md` description as the line:** lost to R1-2; descriptions run 129 to 195 characters and some carry em dashes.
- **The bare skill name as the title:** lost to R4-1; `display_name` sits in the same file as the line and reads better in the docs set.
- **Outlines or a PNG card where the embedded fonts fail to render:** lost to R5-1; system fonts keep the text readable and testable, and R2-1 stays unchanged.

## Simplicity Case

- **Simplest complete design:** one script that concatenates SVG text from two YAML fields and the skill name, three tracked binary inputs (two fonts, one logo), six committed SVGs in genie, 18 in the docs, and one text test.
- **Added machinery:** the `--check` mode, because R2-2 asks a test to catch a stale README card and the comparison is the generator itself; the wrap and title-length refusals, because the script measures no glyphs and a silently overflowing card is worse than a refused one; the missing-submodule refusal, because this host already has an empty `.docs-vendor`; the XML escape, because the text comes from files any skill author edits; the system font stacks, because R5-1 accepts system fonts on a platform that does not draw the embedded ones.
- **Deferred until measured:** a font subsetting step per card (each card carries about 130 KB of fonts and logo; revisit if a platform rejects that size); glyph measurement instead of a character count (revisit when a description that fits in 68 characters visibly overflows); checking the docs cards in CI (revisit only if R3-3 is reopened); any render fallback beyond system fonts (revisit only if the first card's logo or glow fails, which stops the work for the owner).
- **Complexity removed:** no browser, no rasterizer, no network fetch, no runtime or release-pipeline change, no new dependency, no README or docs-page edits, no CI step beyond one test file in the existing `bun test`.
