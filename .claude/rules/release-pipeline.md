# Release-pipeline gotchas

Moved verbatim from CLAUDE.md `## Gotchas` by issue #2967; the always-on floor and
the rules index live there. This file loads when Claude reads a file matching a
`paths:` glob above; a grep-only session never loads it.

- **`genie update` verifies a public release with NO GitHub credential — `gh attestation verify` is an advisory cross-check, never the gate** — the mandatory half runs in-process from the release's own signed delivery evidence (`verifyDeliveryEvidenceArtifact`, `src/lib/delivery-evidence-verify.ts`): the `<tarball>.<channel>.delivery.json` descriptor plus its `.sigstore.json` bundle, checked against the EMBEDDED public-good Sigstore trust root with the `release-publish.yml@refs/heads/main` certificate identity and the GitHub OIDC issuer pinned, the custom `delivery-evidence/v1` predicate type required, the DSSE subject required to equal sha256 of the exact descriptor bytes, and the descriptor's `artifactSha256` bound to sha256 of the downloaded tarball before anything is extracted (`installedBinarySha256` + `canonicalPayloadSha256` bind after extraction, in `runDelivery`). No network, no `gh`, no `cosign` binary. The sign-attest.yml tarball attestation is then cross-checked through `gh attestation verify` when a usable gh exists; `classifyAttestationCrossCheck` (`src/genie-commands/update.ts`) splits its failures into `unavailable` (no gh, gh too old, no credential, network/timeout → ONE transcript line `gh attestation cross-check unavailable (…) — release verified offline from its signed delivery evidence`, update proceeds) and `failed` (gh ran and says the artifact does not verify → abort). Until 2026-09-16 the gh call WAS the only verifier, so `genie update --stable` exited 1 on every host without `gh auth login` even though every release is public; that must never come back. The DOWNLOAD has the same split: `gh release download` first, and when the gh failure classifies as `unavailable` the assets are pulled straight from `https://github.com/automagik-dev/genie/releases/download/v<version>/...` built from the PINNED owner/repo constants (never from `tarball_base`), so a host with no `gh` at all still updates; a gh that ran and answered (`release not found`) is still a hard failure. Missing/tampered delivery evidence aborts BEFORE the cross-check, so an unauthenticated host can never be talked into skipping the floor. Both splits hinge on `isGhUnavailable`, which matches TEXT, and the "binary is missing" wording is RUNTIME-SPECIFIC: Node's `child_process` says `spawn gh ENOENT` while Bun — the runtime the shipped single-file binary actually runs on — says `Executable not found in $PATH: "gh"` with the errno only on the error object. Listing Node's spelling alone is why `genie update` still exited 1 on hosts with NO `gh` at all after the 2026-09-16 fix, green unit tests notwithstanding: the fixtures hardcoded the Node string. `runCommandSilent` now appends the spawn error's `code` (so `\bENOENT\b` matches under any runtime) and the pattern list carries the Bun literal too; never assert a spawn-failure transcript against one runtime's wording.
- **A dev release that fails after its tag was pushed cannot be re-run — only the next merge to dev republishes** — `version.yml` (the main copy, triggered by `workflow_run` of CI on dev) allocates a fresh build number every time and only calls `release.yml` after its own atomic push of the new `[auto-version]` child succeeds. Once dev's tip already is that child, every re-run of the Version run (`gh run rerun`, `--failed` or full) rebuilds a sibling, hits `release-race.next-tag-pin-skipped.detected`, and skips the Release job; `release.yml`'s manual dispatch only offers `channel=stable` and `release-guard.sh` rejects a human dev dispatch; `sign-attest.yml`/`release-publish.yml` are `workflow_call`-only. Re-running failed *jobs* inside one attempt is fine for a transient GitHub error, but endorsements from different attempts make the security gate fail with `verified signer run disagreement`. Observed 2026-09-15 (v5.260915.5 became an orphan tag): land any commit on dev through a normal PR and the next Version run ships the same tree as the next build number.
- **Post-delivery convergence is an argv-only handoff, never an environment-only re-exec** — the 2026-07-11 downgrade incident proved that an old target can ignore an environment-only sync contract and perform a second full update. Today `genie update` invokes the freshly installed binary as `update --post-delivery-converge`: an explicit argv protocol that pre-contract binaries reject at commander parse time, with the mode resolved before any mutation and the lifecycle lease borrowed under an exact-owner record (the parent stays the sole lease owner). Never replace this with an environment-variable-only convergence signal. The post-convergence half of the old two-hop upgrade is gone: the freshly installed binary converges the skills channel itself, so there is no second activation command to run afterwards.
