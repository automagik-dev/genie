# Workflows-channel gotchas

Moved verbatim from CLAUDE.md `## Gotchas` by issue #2967; the always-on floor and
the rules index live there. This file loads when Claude reads a file matching a
`paths:` glob above; a grep-only session never loads it.

- **The workflows channel is the skills channel's rules applied to ONE directory** — `genie install` / `genie update` deliver every `.claude/workflows/*.js` this release ships into Claude Code's user scope `~/.claude/workflows/` (`src/lib/workflows-installer.ts`), read from `<GENIE_HOME>/templates/workflows/` — staged into the existing `templates/` payload member by `scripts/build-binary.sh` and already converged by `convergeAuxiliaryTree` before the channel runs, so there is no second tracked copy and no new tarball member. The catalog ships WHOLE, including the names with no front-door skill (`pm-ledger-verify`, `observability-review`): a filter would be a second list to keep in parity. The result is ONE optional field on the SAME `skills-install.json`: `workflows: {dir, ref, files: <name> → sha256}` — one record so doctor and uninstall keep one authority, optional for the same decision-2 reason as `source` (a required field invalidates every record on disk and disarms `genie uninstall`), and carried forward VERBATIM by the skills channel, which rewrites that file on every run — dropping it would orphan every installed workflow file on the next update. NO RECORD, NO INSTALL: consent `none`, no `~/.claude` (genie creates no product home and never makes one), or a record absent or malformed after the skills channel ran each write NOTHING and say which (`workflows: skipped (…)`); a file genie cannot record is a file `genie uninstall` can never remove. BACKUP FIRST: a file matching neither the recorded nor the delivered digest is archived under `<GENIE_HOME>/state-backups/workflows-collision-<compact ISO>/` and named (`was modified locally` when the record names it, `was not installed by genie` when it does not) before being replaced; one matching the RECORDED digest is genie's own stale copy and is replaced silently; one already matching the DELIVERED digest is left alone, so a second run creates no backup root. A catalog name this release DROPS is archived and removed only while its digest still proves it, otherwise preserved, reported, and kept in the record under its recorded digest so the next update retries it. Ordering is load-bearing on the update seam: the channel runs after the skills channel, because it appends to the record that channel just rewrote. It used to run after the plugin-era retirement too, which owned the one file both touched (a `managed-clean` plugin-era workflow file plus its `.genie-sync.json` sidecar); that module left with v6, so a plugin-era workflow file still on a host is now archived as `not installed by genie` — bytes backed up first, nothing lost, a known bounded cosmetic on a host that never updated through a 5.x release. `genie doctor` observes it read-only, including under `--fix`, as one `workflows: catalog — <present>/<total> in <dir> @ <ref>` line: warn on a `modified`, `missing` or non-regular-file entry (up to five named) or on a `(stale, binary is <tag>)` record, `(unrecorded)` with no field — and that unrecorded line is not merely a shrug: it lstats the names THIS release ships (`shippedWorkflowNames`, never a list written down in doctor) inside `~/.claude/workflows` and warns `(unrecorded) <n> file(s) genie did not record: <names>`, which is the 2026-09-15 stale-user-copy shape on a host the channel has not run on yet; it walks the shipped names rather than listing the user dir, so a workflow outside genie's namespace is structurally invisible and a symlink is named `not a regular file`, never resolved — `not detected` with no `~/.claude`, and a MALFORMED record prints no workflows line at all because `skills: channel` already names that one fault and its one remedy. `genie uninstall` deletes only a recorded file whose digest still matches, `rmdir`s `~/.claude/workflows` only when it ends up empty (the directory is Claude Code's, not genie's), and a preserved file keeps GENIE_HOME AND the record — which is why the workflows sweep runs BEFORE the skills sweep, whose clean run deletes that record. Invocation is by EXPLICIT SCRIPT PATH, never a bare name: both scopes now legitimately carry every name and their resolution order is undocumented (on 2026-09-15 a stale user-scope copy of a catalog name shadowed this repository's own project copy), so the six front-door skills name the project file, then `~/.claude/workflows/<name>.js`, and seven parity tests pin that rule through `scripts/workflow-front-door-parity.ts`.
