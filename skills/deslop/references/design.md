# Design

The interface part, loaded only for a project that has an interface. The shared
method stays in the skill body; this file carries only what interface work adds
to it. When the interface cannot be rendered, or an interaction cannot be
exercised, report that exact gap and make no claim about how the result looks.

## Ground the design

Read the existing design system, tokens, components and brief before choosing
styling. Establish the primary user task and the content or controls it
requires. Reuse existing brand choices, and ask only when an unresolved choice
materially changes the direction. A cleanup preserves product intent and
behaviour; a review produces findings, not edits.

For a new design, choose an appropriate hierarchy, density, type, colour and
layout from the brief and useful references. For an existing design, make the
smallest coherent improvement. Visual personality should fit the product, its
audience and its content, so a familiar component or a dense screen can be the
right answer; imposing a new visual identity to demonstrate taste is a rewrite
wearing a cleanup.

## Build or clean

Check whether each section, card, badge, icon, animation and sentence
communicates something the user needs. Remove duplicate explanations and
decoration that competes with the task. Preserve meaningful grouping, status
signals, navigation and labels. Prefer shared tokens and components to repeated
local fixes.

Generic gradients, repeated feature grids, oversized shadows, tiny copy and
nested cards are clues to inspect, not automatic violations. Plain system fonts,
purple brand colours, rounded cards or a deliberate serif can each be
appropriate, and replacing them with one interchangeable editorial template
fails the same way the original did. Invented testimonials, usage statistics,
live indicators and product capabilities give the user nothing to rely on.

Keep visible labels, keyboard operation, focus states, sufficient contrast and
non-colour status cues, and respect a reduced-motion preference. Verify the
loading, empty, error, disabled and success states the change actually reaches
instead of styling one resting screenshot. Keep localized copy natural in its
own idiom and leave room for the length each language really takes.

## Verify the result

Inspect the rendered interface at the narrow and wide sizes that matter, and
exercise the primary task and every changed state, keyboard interaction
included. A source scan is a lead; it cannot prove visual quality or
accessibility.

Check that the cleanup has not hidden needed information behind extra clicks or
made a control harder to recognize. Report the user-facing improvement, the
visual or interaction evidence behind it, and the limitations that remain.
Leave an effective design alone: an empty findings list is a valid result.
