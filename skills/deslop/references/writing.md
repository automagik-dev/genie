# Writing

The prose half. The shared method stays in the skill body; this file carries
only what prose work adds to it.

## Establish what must survive

Read the supplied text and the brief behind it. Infer audience, purpose, format
and register from the context you already have, and ask only when the missing
answer would change the work. Notice the distinctive cadence, humour, bluntness,
declared uncertainty and useful detours — those are the voice, not noise to sand
off. Protect names, quantities, claims, citations, requirements and causal
links. In narrative, also protect characterization, continuity, tension and
emotional transitions. A detail can matter later even when it looks expendable
where it sits.

## Draft, edit, or review

- Draft from the actual message and the actual evidence. Generic introductions,
  invented statistics, testimonials, borrowed opinions and examples presented as
  facts each add reading work and none of them add information.
- In an edit, remove whole redundant passages and reorganize where that improves
  the reader's path. Keep the good sentences. Where deleting would lose useful
  meaning, rewrite instead. Preserve the author's stance and degree of certainty.
- In a review, identify concrete passages, explain the burden each one imposes,
  and suggest the smallest useful fix. Do not rewrite the piece, and do not
  guess who wrote it.

## What tends to signal avoidable work

Duplicated ideas, vague importance claims, interchangeable promotional
sentences, unnecessary caveats, synonym cycling, forced contrasts, decorative
formatting, repeated sentence patterns, and endings that restate the answer.
Every one of these is a contextual clue, and the body's rule holds: judge the
instance, never the pattern.

Replace abstraction with the available facts or a clearer mechanism. Where the
evidence is missing, keep the uncertainty or name the gap; never invent
specificity to fill it. Use familiar language while keeping precise domain
terms. Adapt idiom directly rather than translating one language's corporate
register into another. Match a required formal register, and leave quoted text,
code, structured data and contractual wording alone unless the request covers
editing them.

## Audit the draft once, then stop

A draft you just wrote reads as finished to you because you wrote it. Before
returning it, read it back and answer one question in a sentence or two: what
still reads as machine-assembled here? Name the tells you actually find, revise
once to address them, and return the revised text. One loop, not a cycle — a
repeated audit keeps finding new tells and grinds the voice flat.

## Return the usable result

For drafting or editing, return the text itself; add an explanation only when it
was requested or when a consequential ambiguity needs the caller's decision. For
a review, return the findings and stop. If nothing worthwhile needs changing,
say so — that is a result, not a failure.
