## Question (authored for the training suite)

```text
This app integrates an external CLI called rtk. How does it find the binary on a machine, what happens on Windows versus everywhere else, and what timeouts and retry limits bound the download and unpack path? Answer with path:line citations.
```

## Reference answer (authored, and the source of the checklist)

```text
**Locating the binary.** Lookup is delegated to the platform's own resolver, chosen at `src/main/services/RtkService.ts:180`: `where.exe` on Windows and `which` everywhere else. That is the PATH branch; a managed installation is probed before it, and only a binary that answered `--version` is accepted from either.

**Bounding the install path.** Three separate timeouts, deliberately different because they bound different things:

- the metadata/API call — `src/main/services/RtkService.ts:32`;
- the body download, which is far longer because it is a real transfer — `src/main/services/RtkService.ts:33`;
- the unpack — `src/main/services/RtkService.ts:34`.

**Retries** are bounded too: the attempt ceiling is `src/main/services/RtkService.ts:357`, so a flapping network fails in bounded time instead of spinning.

```
