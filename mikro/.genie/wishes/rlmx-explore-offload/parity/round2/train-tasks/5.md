## Question (authored for the training suite)

```text
In this desktop app, terminal sessions are backed by real PTY processes. Where are the live sessions tracked, how is a resize applied, how is a process shut down and with what timeout, and is there anything special about the environment a PTY is given? Cite path:line for each answer.
```

## Reference answer (authored, and the source of the checklist)

```text
**Tracking.** Live sessions are held in a module-level map keyed by session id, `src/main/services/ptyManager.ts:38`. Everything else in the module looks up through it, so there is one registry rather than per-window state.

**Resize.** A resize is an explicit call taking columns and rows for a session id — `src/main/services/ptyManager.ts:695` — not a side effect of a render.

**Shutdown.** Termination is graceful-then-forced, on a fixed budget: the timeout constant is `src/main/services/ptyManager.ts:708`, and the kill helper takes it as its default so a caller can override per call rather than editing the constant (`src/main/services/ptyManager.ts:727`).

**Environment.** The PTY environment is not the parent's verbatim. A reserved-key set at `src/main/services/ptyManager.ts:127` names the variables that are managed by the app and must not be inherited or overridden by a caller-supplied environment.

```
