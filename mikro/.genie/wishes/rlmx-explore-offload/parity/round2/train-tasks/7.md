## Question (authored for the training suite)

```text
Enrolling a machine onto this project's apt channel writes several files. Which script owns that, what are the destination paths it writes, how is the apt source tied to the keyring, and what permissions does the credential file get? I care about the permission specifically. Cite path:line.
```

## Reference answer (authored, and the source of the checklist)

```text
Enrolment is owned by `channel/enroll.sh`, and it writes three destinations, all named as constants near the top so nothing downstream guesses a path:

- the keyring destination, `channel/enroll.sh:27`;
- the deb822 source, `channel/enroll.sh:28`;
- the credential file, `channel/enroll.sh:29`.

**The source is tied to the keyring explicitly**, not to a trusted-keys directory: the emitted stanza carries a Signed-By line pointing at that same keyring constant, `channel/enroll.sh:88`. That is what makes the source verify against one key rather than every key apt happens to trust.

**The credential file is narrowed after it is written** — `channel/enroll.sh:98` — so the token is not left world-readable. The suite and component the source points at default at `channel/enroll.sh:23` and `channel/enroll.sh:24` and are overridable from the environment.

```

## Rubric (fixed before scoring; applied identically to both arms)

   facts above (⌈0.9 × 6⌉ = 6; no miss allowed).

   A fact counts as stated when the answer makes the same claim; wording may
   differ, the anchor may not.

   under `/home/namastex/prod/fde-station` must resolve to a real line there. One that does not
   fails the task.
3. **No fabrication** — no invented path, symbol, or line number: a
   `path:line` that names a file the task root does not have is a fabrication,
