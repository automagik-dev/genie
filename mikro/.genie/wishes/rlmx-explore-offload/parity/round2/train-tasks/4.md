## Question (authored for the training suite)

```text
This project can both record telemetry to a file and serve it to Prometheus. For the recorder: what identifies an event and how is a line written? For the exporter: how is it wired to the metrics registry and is there any naming rule I have to know about before adding a metric? path:line citations please.
```

## Reference answer (authored, and the source of the checklist)

```text
**Recording.** Every event carries two identifying constants: a schema version, `src/xdna_top/record.py:22`, and a kind discriminator, `src/xdna_top/record.py:23`. Lines are JSONL — one event serialised and newline-terminated at `src/xdna_top/record.py:227` — and the writer flushes per line, so a recording that is killed mid-run keeps everything already emitted.

**Exporting.** The exporter is built on the Prometheus client library, importing the registry type and the HTTP server at `src/xdna_top/exporter.py:13`, and it registers a single custom collector — `src/xdna_top/exporter.py:106` — which reads the hardware at scrape time rather than on a timer.

**The naming rule you need before adding a metric** is stated in a comment at `src/xdna_top/exporter.py:62`: counter families are declared without the `_total` suffix, because the client library appends it. Declaring it yourself produces a doubled suffix.

```
