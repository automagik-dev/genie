## Question (authored for the training suite)

```text
This repository ships a provider for a gateway called khal. Where is that provider defined, which environment variables can supply its credential and in what order, and what are the distinct failure modes it can report? I also want to know how it converts the gateway's advertised prices into the units the rest of the code uses. Cite path:line for everything.
```

## Reference answer (authored, and the source of the checklist)

```text
All of it lives in one module.

**Identity.** The provider id is a constant, `src/khal-provider.ts:40`, so nothing matches on a bare string literal elsewhere.

**Credential.** Two environment variables are accepted, in a fixed order, from the list at `src/khal-provider.ts:74`: the plain name first, the namespaced one as a fallback. The resolution order matters because a diagnostic that tells the user which variable to edit has to name the one that actually won.

**Failure modes.** Three, and they are deliberately distinct rather than one generic error: a missing credential (`src/khal-provider.ts:55`), a credential the gateway refused (`src/khal-provider.ts:63`), and a gateway that answered but advertised no usable models (`src/khal-provider.ts:71`). The third is a real state, not a variant of the second — an authenticated client can still get an empty catalogue.

**Prices.** The gateway quotes dollars per million tokens; the conversion into per-token dollars is `src/khal-provider.ts:148`.

**One more filter worth knowing:** the catalogue is not taken wholesale — the set at `src/khal-provider.ts:103` names the modes that are not chat completions and are therefore excluded.

```
