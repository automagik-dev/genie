**Root cause — the suspicion is confirmed.** Line 122 seeds `forbiddenRoots` with `canonicalCwd` **unconditionally**, independent of whether the cwd is a git repository. `isSameOrContainedPath` (lines 17-22) returns true for any path *at or beneath* a root:

```ts
const rel = relative(normalizedRoot, normalizedCandidate);
return rel === '' || (rel !== '..' && !rel.startsWith(`..${sep}`) && !isAbsolute(rel));
```

So when `genie install` runs from `~`, `childCwd` = `process.cwd()` = `/home/namastex`, and the candidate `~/.local/bin/codex` is *contained* in it → `rel` = `.local/bin/codex` → refused. The name/intent is "repository-local," but the implementation treats **any cwd, even a non-repo home directory, as a forbidden repo root**. The enclosing-git-root walk (`resolveEnclosingGitTrustRoots`, lines 86-108) would *not* have flagged `~` on its own (no `.git`); the raw `canonicalCwd` entry is what does the damage.

**childCwd = process.cwd() confirmed:** `src/lib/runtime-integrations.ts:481-490` (`resolveRuntimeExecutable` → `validateTrustedExecutablePath(..., cwd)`), fed by `const cwd = options.cwd ?? process.cwd()` at `runtime-integrations.ts:1838` and `:3732`.
