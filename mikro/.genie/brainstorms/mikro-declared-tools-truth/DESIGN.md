## Problem

A microagent that declares `tools:` in `agent.yaml` runs tool-less on the default `mikro mcp` backend with no warning, and on the SDK path its file-loaded tools carry no schema, so `rlmDriver` silently degrades to one-shot — the agent fabricates an answer instead of calling what it declared. Brain's `_ask-maestro` pack reproduced this in 5.6 s with invented file names, which makes every tooled pack untrustworthy on mikro today.

Verified at `14bf5e8`: `LegacyMikroBackend.run` ignores its `agent` argument (`src/mcp/backends/legacy.ts:29-33`); only `prime-sdk` calls the loaders (`src/mcp/backends/prime-sdk.ts:681-683`); all three loaders register without a schema (`src/sdk/tool-loader.ts:162`, `src/sdk/python-plugin.ts:318`, `src/sdk/rtk-plugin.ts:132`); `rlmDriver` selects one-shot whenever `listSchemas()` is empty (`src/sdk/rlm-driver.ts:287-290`), and `tests/sdk-rlm-driver-tools.test.ts:105` pins that silent fallback.

## Scope

### IN
- **Sidecar schema channel.** `tools/<name>.schema.json` next to the plugin file, with exactly the `ToolSchema` shape (`src/sdk/tool-registry.ts`): a JSON object whose only allowed keys are `description` (string) and `parameters` (a JSON Schema object whose `type` is `object`, because the bridged stub is `**kwargs`); `{}` is valid. Both `loadPluginTools` and `loadPythonPlugins` attach it via the existing `registry.register(name, handler, schema)`; a present-but-malformed sidecar throws `InvalidPluginError` naming the file and the parse/shape reason; an absent sidecar registers schema-less as today.
- **Loud `rlmDriver`.** When `config.tools` is supplied and zero tools remain after applying `expose` (the same set `buildPiTools` sends to the model, `src/sdk/rlm-driver.ts:242-258`), `rlmDriver` throws `NoExposableToolsError` at construction. The message names the handlers that lack schemas and the next step: `rlmDriver: tools supplied but no exposed tool has a schema (handlers without schema: a, b). Add tools/<name>.schema.json next to each plugin, call register(name, handler, schema), or omit \`tools\` to run one-shot.` One-shot mode is reached only by omitting `tools`. The pinned fallback test and the JSDoc on `RlmDriverToolsConfig.registry` (`src/sdk/rlm-driver.ts:100-103`, plus the header comments at `:7-11` and `:278-280`, which ship in the published `.d.ts`) are rewritten to state the new contract.
- **Default backend loads declared tools.** `LegacyMikroBackend.run` resolves `agent.spec.tools` through the same two loaders `prime-sdk` uses into a fresh per-run registry, then hands `rlmLoop` a new optional `RLMOptions.tools` typed as the existing `ToolResolver` (built with the existing `toolRegistryAsResolver`, `src/sdk/tool-registry.ts:131-150`), so `rlm.ts` depends on one function type and the registry stays inside `backends/legacy.ts`. `loadPythonPlugins` is called with `timeoutMs` strictly below the REPL execute timeout (`defaultReplTimeoutMs()` in `src/repl.ts:81`, exported, minus a fixed margin), so a slow subprocess plugin fails inside the REPL turn as a normal error instead of killing the REPL. Each loaded tool becomes one generated Python stub appended to `config.tools` (the existing `ToolDef[]` channel that TOOLS.md tools already use, so it is injected into the REPL at start, replayed by crash recovery through `_startOptions.tools` (`src/repl.ts:170-175, 343`), and listed in the system prompt by `buildCustomToolsSection` without new prompt code). A declared name that already exists in `config.tools` from `TOOLS.md` is an UNAVAILABLE cause (`collides with TOOLS.md tool`), never a silent last-wins overwrite (`src/rlm.ts:567-569`).
- **REPL tool bridge.** One new IPC round-trip, mirrored on the existing `llm_request`/`llm_response` pair: Python stub `def <name>(**kwargs)` calls an injected global (added to `_globals` and to `_restore_reserved` in `python/repl_server.py`, sent one line per request under the existing `_ipc_lock` in `python/llm_bridge.py`) → `{"type":"tool_request","tool","args"}` → Node calls the resolver as `(tool, args, signal)` (`ToolResolver`, `src/sdk/agent.ts:166-170`); the `ToolContext` the existing adapter builds carries `iteration: 0` and `sessionId: ""` (`src/sdk/tool-registry.ts:145-146`, matching `src/mcp/backends/prime-sdk.ts:703-708`; threading the live iteration or session id is deferred), emits the existing `ToolCallBefore`/`ToolCallAfter` events nested inside the enclosing `tool: "repl"` pair, and replies `{"type":"tool_response","ok","result"|"error"}`; on `ok:false` the stub raises `RuntimeError(error)` so the model sees a normal REPL error. `metrics.incrToolCalls()` keeps counting REPL executions only. **Invariant: a `tool_request` never rejects the enclosing `execute`.** Every Node-side failure — unknown tool (`UnknownToolError` from the resolver), handler throw (Error or non-Error), non-JSON-serializable result, send failure — becomes `ok:false` plus `ToolCallAfter{ok:false}`; only an `execute_result`, the execute timeout, or subprocess death may settle `execute` (`src/repl.ts:471-477` rejects the whole execute on any throw inside `processMessages`, which is why this must be stated). `ctx.signal` is the run abort signal; it interrupts the handler, not the REPL. Because crash recovery re-executes the failed code block once (`src/repl.ts:220-226, 320-357`), bridged handlers are invoked at-least-once per block; recovery is not changed.
- **UNAVAILABLE for unresolved tools.** A discovery-time probe (`validateAgentTools`, beside `validateAgentModels` in `src/mcp/server.ts`, scoped to `backend: mikro` the same way) checks every declared name of a default-backend agent against `tools/<name>.{mjs,js,py}` using the loaders' own path resolvers (`resolvePluginPath`, `resolvePythonScript`, exported — single source of truth), against the REPL's reserved names, and against `TOOLS.md` names. The reserved set is one exported Node-side constant next to `BATTERY_FUNCTION_NAMES` in `src/repl.ts`, defined as the Python `RESERVED_NAMES` (`context`, `FINAL`, `FINAL_VAR`, `SHOW_VARS`, `llm_query`, `llm_query_batched`, `rlm_query`, `rlm_query_batched`, `python/repl_server.py:36-39`, currently defined but never enforced) ∪ every non-underscore top-level `def` name in `python/batteries.py`, `python/gemini_batteries.py` and `python/pg_batteries.py` (at HEAD: the 8 tracked in `BATTERY_FUNCTION_NAMES` plus `run_cli`, the 3 Gemini names, and the 6 `pg_*` names), because all three battery files load after `options.tools` (`src/repl.ts:170-190`) and a stub with any of those names would be silently replaced at the matching tools level. A parity test derives the Python side by reading the `^def ` lines of those three files and `RESERVED_NAMES`, so a future battery cannot drift from the constant; the stats-tracking constants are not the source. Any miss replaces the current `Microagent.modelProblem` with a single `Microagent.unavailable` sentence that already includes its remedy, set by whichever validator fires first, so `describeAgent`, the startup stderr line and the `tools/call` refusal (`src/mcp/server.ts:186-190, 918-924, 989-993`) keep one branch each. Wording: `UNAVAILABLE — "<name>" cannot run: missing tools: a, b — add tools/<name>.{mjs,js,py} to <agent dir> or remove the declaration, then retry.`; reserved: `"FINAL" is a reserved REPL name — rename the tool and its file.`; collision: `"x" collides with a TOOLS.md tool — rename one of them.` The existing model remedy sentence moves into the model validator's own text. The probe checks resolution only; a plugin that exists but fails to load (`InvalidPluginError`: bad default export, malformed sidecar) still surfaces at `tools/call` as `mikro <name> failed: …` (`src/mcp/server.ts:1088-1092`), exactly as on `prime-sdk`. `prime`/`prime-sdk` agents keep their own run-time check.
- **Truthful `tools/list` description.** Every microagent description ends with `Backend: <mikro|prime|prime-sdk>. Tools: a, b, c.` (or `Tools: none declared.`), derived from the spec. This reports the executing backend, which the handoff M1(c) asks for; setting `backend:` stays an undocumented experiment selector (`src/sdk/agent-spec.ts:108-122`), and the docs say only that the description reports it and that `mikro` is the default.
- **Docs and changelog.** `docs/tool-authoring.md` (exists at HEAD; extend, do not recreate): update the intro at lines 3-6 and the `args` comment at line 15 so a handler is reachable from both `runAgent` tool-call steps and the `mikro mcp` REPL bridge; new sections "Sidecar schema" (the `ToolSchema` interface verbatim, one complete `echo.schema.json`, the validation rule above), "Calling bridged tools from the REPL" (`**kwargs` convention, `RuntimeError` on failure, at-least-once on REPL recovery, `ctx.signal` reach, `.mjs` handlers own their deadline), "Reserved names", "Timeouts on the default backend" (`MIKRO_REPL_TIMEOUT_MS` wraps every call; the `loadPythonPlugins({ timeoutMs })` at line 86 is set below it by the backend), "How tools reach the model on each backend" (why keyword arguments, why RTK is `missing` on the default backend, ESM import cache freezes an edited `.mjs` until restart), one supply-chain line (bridged handlers run in the MCP server process with model-chosen arguments, as on `prime-sdk`). `docs/agent-yaml-schema.md`: the comment at lines 74-76 and the `tools` row at line 116 now cover `mikro mcp`; the UNAVAILABLE rule. `README.md`: the agent.yaml `tools` row at line 207 now says the default backend loads them too, and the `mikro mcp` UNAVAILABLE sentence at lines 900-906 gains the missing-tools/reserved/collision causes and the `Backend:/Tools:` suffix. `docs/events.md:244-260` plugin-shape paragraph points at `tool-authoring.md`. `docs/sdk-overview.md`: the `rlmDriver` contract change. `examples/agents/hello-world/tools/greet.schema.json` added as the tutorial-shaped example. CHANGELOG: one bold-led `### Changed` entry under `[Unreleased]` labelled `(SDK public API)` stating the old fallback, the new throw and the migration, plus an `### Added` entry for sidecar, bridge and the MCP UNAVAILABLE causes (narrative, per the file's Keep-a-Changelog header).

## Approach

**Chosen: bridge registry tools into the REPL, fail loudly at every boundary.** The legacy engine's only tool mechanism is Python code injected into the REPL, and it already has a blocking Python→Node round-trip for LLM calls. Adding a sibling `tool_request` message and a generated `**kwargs` stub per tool is the smallest change that makes a declared tool callable by the model on the default backend, keeps the RLM loop (REPL, recursion, FINAL, sessions, resume, crash recovery) untouched, and reuses the existing `ToolCallBefore`/`ToolCallAfter` events and the existing `ToolResolver` seam. Missing files, reserved names and TOOLS.md collisions are caught where the model-pin check already lives, so every UNAVAILABLE cause renders and refuses identically.

Alternatives considered:
- **Switch tooled agents to `runAgent` + `rlmDriver` native function-calling on the default backend.** Rejected: replaces the engine for those agents (no REPL, different session/resume/validate semantics, different prompt), a far larger blast radius, and contradicts the index's standing decision that the mikro engine stays the default.
- **Auto-select `prime-sdk` when `tools:` is declared.** Rejected: hides a hard dependency on an external `prime-agent`, conflicts with the Ready design `mikro-prime-081-reconciliation` (Prime only after its own gates), and does nothing for the SDK path.
- **Advertise UNAVAILABLE for any `tools:` on the default backend and stop.** Honest but fails need M1(a); brain's packs would be unrunnable without prime. Kept as the fallback shape for unresolved names only.
- **Schema by named export / handshake instead of sidecar.** Rejected as the sole channel: a sidecar file works for `.mjs`, `.js` and `.py` with one parser and one test; the others are per-language and would be a second source of truth.
- **Pass the `ToolRegistry` itself into `rlmLoop`.** Rejected: `rlm.ts` would take on the registry interface while using only `get`; the existing `ToolResolver` function type already encodes unknown-tool handling.

Design for isolation:
- `tool-loader.ts` / `python-plugin.ts`: read sidecar, export path resolvers. Testable without a REPL or MCP.
- `repl.ts` + `python/repl_server.py` + `python/llm_bridge.py`: `tool_request` transport and the injected `call_tool` global; exported reserved-name constant. Testable with a fake resolver and no LLM.
- `rlm.ts`: `RLMOptions.tools: ToolResolver` → `repl.onToolRequest` + events. One function type, no shared mutable state.
- `backends/legacy.ts`: load, timeout option, stub generation, resolver adaptation. Testable through the existing `loop` seam.
- `mcp/server.ts` + `mcp/agents.ts`: `unavailable` field, tools probe, description suffix. Testable with temp agent dirs like `tests/mcp-agents.test.ts`.

## Simplicity Case

- **Simplest complete design:** sidecar schema read by the two existing loaders; `rlmDriver` throws instead of silently switching modes; legacy backend loads declared tools, generates one `**kwargs` stub per tool into the existing `config.tools` channel, and the REPL gains one request/response pair that calls back through the existing resolver type; discovery marks unresolved names UNAVAILABLE through the existing rendering path; description gains one sentence.
- **Added machinery:** the `tool_request`/`tool_response` message pair (required: the REPL is the only place the model can act on the default backend, and Node owns the handlers). The reserved-name and collision checks (required: a stub named `FINAL` would silently break termination, a stub named `context` would overwrite the loaded context, a TOOLS.md duplicate would silently win or lose; each check is a set lookup at discovery). One option value (`timeoutMs` below the REPL timeout) passed to an existing loader parameter. Nothing else — no new config key, env var, backend, retry, or fallback flag.
- **Deferred until measured:** named `schema` export for `.mjs` (trigger: a consumer reports sidecar friction in a filed issue); positional-argument stubs (trigger: traces show a model calling a bridged tool positionally in ≥ 2 packs); a per-tool timeout knob (trigger: a measured plugin call in brain's packs that needs more than the REPL execute timeout); live iteration in bridged `ToolContext` (trigger: a consumer's `ToolCallBefore` handler needs it); exactly-once dispatch across REPL recovery (trigger: a pack with a non-idempotent tool observes a replay); RTK schema (trigger: an agent needing `rtk` via native function-calling).
- **Complexity removed:** no dual schema channels, no silent one-shot branch when tools were requested, no backend auto-selection, no per-agent "strict tools" option, no parallel `toolProblem`/`modelProblem` branches, no registry type inside `rlm.ts`, no new durable state (the registry is per-run and in-memory; a `tool_response` is consumed inside the same `execute` call that produced its request).

## Decisions

| # | Decision | Rationale |
|---|----------|-----------|
| 1 | Bridge tools into the REPL via a `tool_request` IPC pair; no driver switch on the default backend. Bridged events nest inside the enclosing `tool: "repl"` pair; `incrToolCalls` counts REPL executions only. | Smallest change that makes declared tools callable while keeping the RLM engine and its semantics; the `llm_request` bridge is the proven template. Stating the nesting keeps `--verbose` and event consumers from guessing. |
| 2 | Sidecar `tools/<name>.schema.json` is the single schema channel, shaped exactly like `ToolSchema`, with `parameters.type` required to be `object` when present. | One parser, one test, works for all three plugin languages; also improves `prime-sdk` for free through the shared loaders; a non-object schema has no meaning for a `**kwargs` stub. |
| 3 | `rlmDriver` with `tools` and zero exposed schemas throws `NoExposableToolsError` at construction, with the next step in the message. | Passing `tools` states intent to dispatch; silently running one-shot is the M2 bug. Construction-time is the earliest, cheapest point; checking after `expose` matches what the model would actually receive. The only known consumer (brain) asked for it; the pinned test is rewritten. |
| 4 | Unresolved declared tools, reserved-name collisions and TOOLS.md collisions are found at discovery and carried in one `Microagent.unavailable` sentence (replacing `modelProblem`) with a per-cause remedy; scoped to `backend: mikro` like `validateAgentModels`. The reserved set is one exported Node constant equal to Python's `RESERVED_NAMES` ∪ every non-underscore top-level `def` in the three battery files, pinned by a parity test that reads those files. | `tools/list` must never advertise a tool whose call is guaranteed to degrade; one field keeps the three rendering sites at one branch each and lets each cause carry the right fix; the Node constant is the single source the probe reads. Prime backends own their own tool universe. |
| 5 | Stubs are `def <name>(**kwargs)` with a docstring built from the sidecar description and parameter names; no sidecar → generic docstring `"(arguments undocumented — pass keyword arguments)"`. | Keyword arguments map 1:1 onto a JSON object, which is what every handler already receives; the prompt section already renders `name()` plus docstring. |
| 6 | Handler errors surface as Python `RuntimeError` inside the REPL; tool results are JSON-round-tripped (`undefined` → `null`); a `tool_request` never rejects the enclosing `execute`. | The model already knows how to read REPL errors; JSON is the existing contract for Python plugins and the wire format of the bridge; any bridge failure escaping `processMessages` would end the whole run (`src/repl.ts:471-477`, `src/rlm.ts:940, 1151-1183`). |
| 7 | The description suffix `Backend: … Tools: …` is derived from the spec, not from a load attempt. | `tools/list` runs on every request; the truth about *resolution* is already carried by `unavailable`, so listing declared names is enough and free; the handoff asks for the backend explicitly. |
| 8 | `rlmLoop` receives a `ToolResolver`, not a registry; `iteration` is `0` for bridged calls. | One function type already exists and already handles unknown tools; the other two call sites pass `0`; threading the live iteration would need shared mutable state or a new `execute` parameter and has no consumer yet. |
| 9 | Python plugins on the default backend are loaded with a timeout strictly below the REPL execute timeout (`defaultReplTimeoutMs()` becomes an export of `src/repl.ts`); `.mjs` handlers own their deadline via `ctx.signal`. | At defaults both timeouts are 30 s and the REPL timer starts first (`src/sdk/python-plugin.ts:46`, `src/repl.ts:81-87`), so the plugin timeout could never fire and a slow tool would SIGKILL the REPL and fail the run; one option value restores the "handler error → RuntimeError" contract for the common slow case. |
| 10 | Bridged handlers are at-least-once per code block; crash recovery is unchanged. | Recovery already replays the failed block; tools are the first thing with side effects, so the property is stated and documented rather than hidden. Exactly-once would need new durable state with no present requirement. |

## Risks & Assumptions

| # | Risk | Severity | Mitigation |
|---|------|----------|------------|
| 1 | A bridged tool call runs inside the REPL execute timeout; if a handler outlives it, the REPL is SIGKILLed, the run ends `failed` and REPL state is lost (`src/repl.ts:422-439`, `src/rlm.ts:1157-1183`), the failure class M6 already shows. | Medium | Python plugins get a timeout strictly below the REPL timeout (Decision 9) so they fail as a `RuntimeError` the model can react to; `.mjs` handlers are documented as owning their deadline; `MIKRO_REPL_TIMEOUT_MS` is the existing knob and is named in the docs; a per-tool knob is deferred behind a measured trigger. |
| 2 | `rlmDriver` contract change breaks a consumer relying on schema-less `tools` falling back to one-shot. | Medium | Named error with the next step in the message; CHANGELOG `(SDK public API)` entry; JSDoc in the published `.d.ts` rewritten; the one known consumer requested the change. |
| 3 | Gemini code-execution paths (`toolsLevel` standard/full on Google) run code outside the REPL, where bridged tools do not exist. | Low | Same limitation TOOLS.md tools have today; documented, not changed. |
| 4 | Stub docstring quality drives whether the model calls the tool; packs without sidecars get a generic docstring. | Low | Sidecar is the recommended path and brain's packs ship one per tool; M1 acceptance is checked with sidecars present. |
| 5 | The discovery probe and the loaders could disagree on resolvable extensions. | Low | Both call the same exported resolver functions; a test loads what the probe accepts. |
| 6 | `tools/list` per-request probing adds one `stat` per declared tool per agent. | Low | Same order of cost as reading `VALIDATE.md` per agent today; no caching until measured. |
| 7 | Assumption: brain's declared tools exist as `tools/*.py|.mjs` files in each pack (the handoff states packs are `schema_version: 1 / tools_api: 1` folders). If some names are meant as host-registered in-process tools, they will show as UNAVAILABLE on `mikro mcp` until M3's registration API lands. | Medium | Explicitly accepted; M3 child owns host-registered tools/agents. |
| 8 | Shipping this changes the observed Mikro column of CAP-20 (`SILENT_GAP — MCP legacy ignores spec tools`) and CAP-21 (spec tools vs TOOLS.md tools) in the Ready design `mikro-prime-081-reconciliation`. | Low | That ledger is re-observed by its own process after this ships; this wish does not edit it. Routing stubs through `config.tools` is an implementation channel; spec tools and TOOLS.md tools remain distinct contracts, enforced by the collision check. |
| 9 | A tool with external side effects may run twice when the REPL crashes mid-block and recovery replays it. | Low | Stated (Decision 10) and documented; latent today for `rlm_query`; exactly-once deferred behind a measured trigger. |
| 10 | Renaming `modelProblem` to `unavailable` touches `tests/custom-providers.test.ts:337-345` and four `src/mcp/server.ts` sites (the three renderers at 186-190, 919-921, 989-992 plus the validator assignment at 620). | Low | Mechanical, single module; the parity of the three renderers is exactly what the single field buys. |
